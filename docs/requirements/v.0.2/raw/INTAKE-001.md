# Cash Chat 관리자 운영 시스템 설계

- 작성일: 2026-07-12
- 상태: 검토 요청
- 대상: 별도 관리자 웹·관리자 서버
- 데이터 구성: 서비스 서버와 공통 MySQL DB 사용

## 1. 목적

Cash Chat 서비스의 출시 운영, 고객지원, 보상 정정, 서비스 상태 확인, 마케팅·매출 분석을 위한 별도 관리자 시스템을 정의한다.

관리자 웹은 DB에 직접 접근하지 않는다. 별도 관리자 서버가 공통 DB를 조회·변경하고 관리자 전용 API를 제공한다. 관리자 계정, 권한, 감사 로그, 운영 메모처럼 관리자 시스템에만 필요한 데이터는 관리자 서버가 소유한다.

## 2. 현재 코드베이스 분석

### 2.1 활용 가능한 서비스 데이터

| 영역 | 현재 데이터 |
| --- | --- |
| 회원 | `users`: 역할, 기기 토큰, OAuth 제공자, 이메일, 이름, 가입·수정 시각 |
| 채팅 | `conversations`, `chat_messages`: 대화, 메시지 역할·상태·모델·발생 시각 |
| 포인트 | `user_points`, `point_transaction`: 잔액, 증감, 변경 후 잔액, 사유, 멱등 키 |
| Energy | `user_energy`: 사용 가능 Energy, 예약 Energy |
| 광고 | `google_ad_ssv_events`, 광고 nonce·일일 quota: 검증·보상 상태와 사용 횟수 |
| 오퍼월 | `tnk_offerwall_callbacks`, 사용자 토큰: 플랫폼, 거래, 지급 상태 |
| 출석 | 출석 로그와 일차별 보상 정책 |
| 초대 | 초대 코드, 초대자·피초대자, 지급 상태 |
| 룰렛 | 일일 상태, nonce, 당첨·지급 Energy 이력 |
| 진화 | 회원 등급·경험치, 진화 시도·성공률·결과 |
| 상점 | 상품 카탈로그, 구매 주문, 회원 인벤토리 |
| 정산 | `ledger_entry` 구조는 있으나 실제 광고·오퍼월 처리와 연결되지 않은 휴면 상태 |

### 2.2 새로 필요한 기반

- 관리자 계정, 로그인, 세션, RBAC 권한
- 관리자 변경·민감정보 조회 감사 로그
- 회원 상태, 제재 기간, 탈퇴 상태, 운영 메모
- 로그인·기기·IP 이력
- Energy 변동 원장
- AI 토큰 사용량과 비용 데이터
- 공지, 약관, 문의·VoC
- 동적 운영 정책과 변경 이력
- 상품 이미지·재고·판매 기간·공급업체·상품권 발송 상태
- 서버 메트릭·로그·배포 파이프라인 연동
- 마케팅 채널별 비용·유입·수익 데이터

현재 서비스에는 `ADMIN` 역할이 있지만 관리자 전용 API, 경로별 권한 검사와 감사 기능은 없다. 별도 관리자 인증 체계를 서비스 회원 인증과 분리한다.

## 3. 시스템 구조

```plaintext
관리자 웹
   │ HTTPS / 관리자 전용 API
   ▼
별도 관리자 서버
   ├─ 관리자 인증·세션·RBAC
   ├─ 조회 API
   ├─ 운영 변경 API
   ├─ 집계·보고 API
   └─ 감사 로그
          │
          ▼
      공통 MySQL DB
          ▲
          │
       서비스 서버
```

### 3.1 데이터 접근 원칙

1. 관리자 웹은 관리자 서버 API만 호출한다.
2. 관리자 서버는 공통 DB에서 관리자 화면에 필요한 형태로 검색·필터·페이징·집계한다.
3. 서비스 테이블 변경은 관리자 서버의 도메인 서비스와 트랜잭션을 거친다.
4. 포인트와 Energy는 잔액을 직접 덮어쓰지 않고 원장 거래로 조정한다.
5. 관리자 변경은 업무 데이터와 감사 로그가 함께 성공하거나 함께 롤백되어야 한다.
6. 회원 정지처럼 서비스 동작을 바꾸는 상태는 서비스 서버도 요청 시 검증해야 한다.
7. 초기 통계는 공통 DB에서 조회하되, 부하가 증가하면 집계 테이블·읽기 복제본·분석 DB 순서로 분리한다.
8. 서비스 DB 계정과 관리자 DB 계정을 분리하고 관리자 계정에는 필요한 테이블 권한만 부여한다.

## 4. 역할과 권한

역할명에 기능을 하드코딩하지 않고 `member.read`, `reward.adjust`, `policy.write`와 같은 세부 권한을 역할에 묶는 RBAC를 사용한다.

| 초기 역할 | 주요 범위 |
| --- | --- |
| 슈퍼 관리자 | 관리자 계정·역할, 모든 조회·변경, 감사 로그 |
| 운영·CS 관리자 | 회원 조회·제재, 보상 조사·조정, 주문·문의·공지 처리 |
| 마케팅·분석 관리자 | 대시보드, 광고·매출·사용자 분석, 보고서 조회·다운로드 |

개인정보 원문, 채팅 원문, 자산 조정, 회원 제재, 정책 변경, 파일 다운로드는 각각 독립 권한으로 둔다.

## 5. 우선순위 정의

| 우선순위 | 의미 | 목표 |
| --- | --- | --- |
| P0 | 관리자 시스템 가동 전 필수 | 안전한 인증·권한·감사 및 기본 장애·CS 대응 |
| P1 | 출시 직후 운영 필수 | 회원·보상·광고·채팅·주문 문제를 실제로 조사·처리 |
| P2 | 운영 효율화 | 정책·콘텐츠 관리, 지표 분석, 수동 업무 자동화 |
| P3 | 성장·고도화 | 마케팅 ROI, 정산, 국제화, 어뷰징 자동 탐지 |

## 6. 공통 인수 원칙

- 목록 API는 기본적으로 페이징하며 명시적인 정렬 기준을 제공한다.
- 개인정보는 권한이 없으면 마스킹하고, 원문 조회와 다운로드를 감사한다.
- 변경 API는 처리 사유, 요청 식별자, 낙관적 잠금 또는 현재 버전을 요구한다.
- 동일 요청 식별자의 재요청은 중복 변경 없이 기존 결과를 반환한다.
- 변경 전 확인 이후 데이터가 바뀌면 충돌을 반환하고 최신 값을 다시 확인하게 한다.
- 모든 날짜·일일 한도·집계 기준은 `Asia/Seoul`로 통일한다.
- 관리자 화면의 합계와 상세 조회는 동일한 필터·시간 기준을 사용한다.

## 7. 유저 스토리

### 7.1 관리자 인증·권한

#### US-ADM-AUTH-001 관리자 로그인 [P0]

> 관리자로서 인가된 운영 시스템 접근을 위해 관리자 계정으로 로그인할 수 있다.

- AC-01 정상 로그인: 활성 관리자 계정이 존재할 때 올바른 아이디·비밀번호로 로그인하면 인증 세션을 발급하고 허용된 초기 화면 정보를 반환한다.
- AC-02 인증 실패: 아이디가 없거나 비밀번호가 불일치하면 구체적 실패 원인을 노출하지 않고 동일한 실패 응답을 반환한다.
- AC-03 반복 실패 잠금: 동일 계정 인증 실패가 정책 횟수에 도달하면 계정을 일정 시간 잠그고 시도 내역을 기록한다.

#### US-ADM-AUTH-002 관리자 계정 관리 [P0]

> 슈퍼 관리자로서 운영 인력의 접근 통제를 위해 관리자 계정을 생성하고 비활성화할 수 있다.

- AC-01 생성: 관리자 계정 관리 권한이 있을 때 이름·로그인 ID·역할을 입력하면 중복되지 않은 계정을 생성한다.
- AC-02 비활성화: 슈퍼 관리자가 사유를 입력해 비활성화하면 모든 세션을 만료시키고 새 로그인을 차단한다.
- AC-03 자기 계정 보호: 자신의 계정 비활성화 요청은 거부한다.

#### US-ADM-AUTH-003 역할별 권한 관리 [P0]

> 슈퍼 관리자로서 업무 범위에 맞는 접근 통제를 위해 관리자 역할과 세부 권한을 관리할 수 있다.

- AC-01 권한 구성: 역할에 조회·변경·다운로드 권한을 부여하면 다음 API 요청부터 적용한다.
- AC-02 서버 검증: 권한 없는 관리자가 API를 직접 호출하면 `403 Forbidden`으로 거부한다.
- AC-03 메뉴 제한: 로그인 시 허용된 메뉴와 동작만 노출한다.

#### US-ADM-AUTH-004 세션·추가 인증 [P1]

> 관리자로서 계정 탈취와 방치된 로그인 정보의 악용 방지를 위해 세션과 추가 인증을 안전하게 관리할 수 있다.

- AC-01 유휴 만료: 정책 시간 무활동 후 다음 API 호출 시 세션을 만료시키고 재로그인을 요구한다.
- AC-02 추가 인증: 비밀번호 인증 통과 후 등록된 추가 인증 수단을 검증한 뒤 세션을 발급한다.
- AC-03 로그아웃: 로그아웃 시 서버 세션을 무효화하고 재사용을 차단한다.

### 7.2 감사·보안

#### US-ADM-AUDIT-001 관리자 변경 감사 [P0]

> 감사 담당자로서 운영 변경의 책임과 경위를 추적하기 위해 관리자 작업 이력을 조회할 수 있다.

- AC-01 변경 기록: 제재·자산 조정·설정 변경 트랜잭션 처리 시 기능, 대상, 처리자, 사유, 전후 값, 시각과 IP를 기록한다.
- AC-02 원자성: 감사 로그 저장 실패 시 업무 데이터 변경도 롤백한다.
- AC-03 불변성: 저장된 감사 로그의 수정·삭제 시도는 거부한다.

#### US-ADM-AUDIT-002 민감정보 조회 감사 [P0]

> 감사 담당자로서 개인정보 오남용 방지를 위해 민감정보 조회 이력을 확인할 수 있다.

- AC-01 회원정보 조회: 이메일·로그인·기기 정보 조회 시 조회자, 대상 회원, 범위, 시각과 IP를 기록한다.
- AC-02 채팅 원문 조회: 권한 보유자가 사유를 입력해 원문을 조회하면 사유와 조회 범위를 감사 로그에 기록한다.
- AC-03 다운로드: 개인정보 포함 파일 생성 시 검색 조건, 포함 범위와 관리자를 기록한다.

#### US-ADM-AUDIT-003 위험 작업 확인 [P0]

> 운영 관리자로서 실수로 인한 피해 방지를 위해 위험한 변경의 대상과 결과를 확인할 수 있다.

- AC-01 사유 필수: 제재·자산 차감·재처리에서 사유 미입력 시 실행하지 않는다.
- AC-02 재확인: 최종 실행 전 대상, 현재 값, 변경 값과 예상 결과를 표시한다.
- AC-03 충돌 방지: 확인 이후 대상 데이터가 변경되면 충돌을 반환하고 최신 값 재확인을 요구한다.

### 7.3 대시보드

#### US-ADM-DASH-001 핵심 운영 현황 [P1]

> 운영 관리자로서 서비스 이상과 운영량을 빠르게 파악하기 위해 핵심 지표를 한 화면에서 조회할 수 있다.

- AC-01 기간 지표: 오늘·주간·월간 대시보드 조회 시 신규·탈퇴 회원, 채팅, 광고 보상, 포인트·Energy, 구매 지표를 같은 기간 기준으로 반환한다.
- AC-02 성공·실패 구분: 채팅·광고·오퍼월의 요청 수와 성공·실패·거절 수를 구분한다.
- AC-03 상세 이동: 지표 카드 선택 시 동일 기간·상태 필터가 적용된 상세 목록으로 이동한다.

#### US-ADM-DASH-002 회원 활성 지표 [P1]

> 마케팅·분석 관리자로서 서비스 이용 추세를 파악하기 위해 가입자와 활성 회원 지표를 조회할 수 있다.

- AC-01 가입자: 날짜 범위 선택 시 신규 회원과 가입 유형별 수를 일 단위로 반환한다.
- AC-02 활성 회원: 활동 이벤트 정의가 확정된 상태에서 DAU·WAU·MAU 조회 시 중복 제거한 활성 회원 수와 정의를 함께 표시한다.
- AC-03 비교: 직전 동일 기간 대비 증감 수와 비율을 반환한다.

#### US-ADM-DASH-003 보상 경제 지표 [P1]

> 운영 관리자로서 보상 경제의 이상을 확인하기 위해 포인트와 Energy의 적립·소비량을 조회할 수 있다.

- AC-01 통화 분리: 포인트, Energy, 진화 경험치를 서로 다른 통화로 집계한다.
- AC-02 채널별 집계: 출석, 채팅, 광고, 오퍼월, 초대, 룰렛, 상점, 관리자 조정을 구분한다.
- AC-03 이상 표시: 임계치 초과 변동 시 이상 지표와 영향 채널을 표시한다.

#### US-ADM-DASH-004 AI 비용 현황 [P1]

> 비용 관리자로서 AI 운영 비용을 통제하기 위해 모델별 사용량과 예상 비용을 조회할 수 있다.

- AC-01 모델별 사용량: 기간 선택 시 모델별 요청, 입력·출력 토큰, 성공·실패 수를 반환한다.
- AC-02 비용 계산: 유효 기간 단가로 예상 비용을 계산하고 통화를 표시한다.
- AC-03 예산 경고: 월간 예산 임계치 도달 시 대시보드에 경고를 표시한다.

### 7.4 회원·제재

#### US-ADM-MEMBER-001 회원 검색 [P0]

> 운영·CS 관리자로서 문의 또는 운영 대상 회원을 찾기 위해 회원 목록을 검색할 수 있다.

- AC-01 조건 검색: ID, 이름, 이메일, 가입 유형, 상태, 가입 기간 조건을 모두 만족하는 회원을 페이징 반환한다.
- AC-02 기본 정보: ID, 이름, 마스킹 이메일, 가입 유형, 상태, 가입일을 반환한다.
- AC-03 개인정보 제한: 원문 권한이 없으면 이메일과 외부 식별자를 마스킹한다.

#### US-ADM-MEMBER-002 회원 상세 조회 [P0]

> 운영·CS 관리자로서 회원 상태를 종합적으로 파악하기 위해 회원 상세정보를 조회할 수 있다.

- AC-01 기본·자산 정보: 가입 정보, 상태, 포인트, 사용·예약 Energy, 진화 등급·경험치를 반환한다.
- AC-02 활동 요약: 채팅, 광고, 출석, 오퍼월, 초대, 룰렛, 구매 누적 수를 반환한다.
- AC-03 미생성 데이터: 미생성 도메인 데이터는 전체 요청 실패 없이 미생성으로 표시한다.
- AC-04 조회 감사: 개인정보 포함 상세 조회 시 대상, 조회자, 범위, 시각을 감사한다.

#### US-ADM-MEMBER-003 회원 이용 제재 [P0]

> 운영 관리자로서 정책 위반 사용자의 서비스 이용을 통제하기 위해 회원을 정지하거나 이용을 제한할 수 있다.

- AC-01 정지·기간 제한: 사유와 선택적 종료 시각 입력 시 상태를 변경하고 활성 인증 토큰을 무효화한다.
- AC-02 서비스 적용: 정지·제한 회원의 로그인·보호 API 호출을 서비스 서버가 공통 DB 상태 검증으로 거부한다.
- AC-03 해제: 권한 있는 관리자가 해제 사유 입력 시 정상 상태로 변경하고 다음 인증부터 허용한다.
- AC-04 감사: 제재 상태 변경 시 전후 상태, 기간, 사유, 처리자를 기록한다.

#### US-ADM-MEMBER-004 회원 활동 통합 조회 [P1]

> 운영·CS 관리자로서 문의와 이상 행동의 원인을 파악하기 위해 회원 활동 이력을 시간순으로 조회할 수 있다.

- AC-01 타임라인: 로그인, 채팅, 자산, 광고, 출석, 오퍼월, 초대, 룰렛, 진화, 구매를 시간순 반환한다.
- AC-02 필터: 유형·기간 조건으로 필터링한다.
- AC-03 원본 연결: 자산 변동 활동은 원본 이벤트, 원장 거래, 변경 후 잔액을 연결한다.

#### US-ADM-MEMBER-005 위험 표시·내부 메모 [P1]

> 운영 관리자로서 의심 회원의 조사 상태를 공유하기 위해 위험 표시와 내부 메모를 관리할 수 있다.

- AC-01 표시 등록: 위험 유형, 사유, 근거 입력 시 회원 상세에 내부 위험 표시를 추가한다.
- AC-02 사용자 비노출: 내부 표시와 메모를 서비스 앱에 노출하지 않는다.
- AC-03 해제 이력: 해제 사유 입력 시 표시를 비활성화하고 과거 이력을 보존한다.

#### US-ADM-MEMBER-006 로그인·기기 이력 [P1]

> 운영 관리자로서 계정 탈취와 다계정 사용을 조사하기 위해 회원의 로그인·기기 이력을 조회할 수 있다.

- AC-01 로그인 기록: 로그인·토큰 갱신 종료 시 회원, 제공자, 성공 여부, 시각, IP, 기기 식별 정보를 기록한다.
- AC-02 회원별 조회: 최신 기록부터 페이징 반환한다.
- AC-03 기기별 탐색: 기기 기준 검색 시 연결 회원과 최근 이용 시각을 반환한다.

#### US-ADM-MEMBER-007 회원 탈퇴 처리 [P1]

> 운영·CS 관리자로서 회원의 탈퇴 요청을 정책에 맞게 처리하기 위해 탈퇴 상태와 개인정보 처리 단계를 관리할 수 있다.

- AC-01 탈퇴 예약: 요청 근거와 처리 예정일 확인 시 탈퇴 예정 상태로 변경하고 활성 인증 토큰을 무효화한다.
- AC-02 보존 정책 적용: 처리일 도래 시 법적·회계 보존 대상과 즉시 삭제·익명화 대상을 구분 처리한다.
- AC-03 재가입 식별 정책: 익명화 후 동일 OAuth·기기 재가입은 확정된 정책에 따라 허용·차단하고 과거 개인정보를 임의 복원하지 않는다.
- AC-04 처리 감사: 상태·처리 단계 변경 시 근거, 처리자, 전후 상태, 결과를 감사 로그에 기록한다.

### 7.5 보상·경제

#### US-ADM-REWARD-001 자산·변동 원장 조회 [P0]

> 운영·CS 관리자로서 보상 적립과 사용 문제를 조사하기 위해 회원의 포인트와 Energy 변동 내역을 조회할 수 있다.

- AC-01 포인트: 현재 잔액, 증감, 변경 후 잔액, 사유, 원본 식별자, 시각을 반환한다.
- AC-02 Energy: 사용·예약 Energy와 광고, 채팅 예약·정산·환불, 초대, 룰렛, 관리자 조정 이력을 반환한다.
- AC-03 정합성: 최신 변경 후 잔액과 현재 지갑 잔액이 일치한다.

#### US-ADM-REWARD-002 포인트 수동 조정 [P0]

> 권한 있는 운영 관리자로서 보상 누락과 오지급을 정정하기 위해 회원의 포인트를 수동으로 지급하거나 차감할 수 있다.

- AC-01 지급·차감: 회원, 금액, 사유, 관련 번호가 유효하면 지갑과 원장을 단일 트랜잭션으로 변경한다.
- AC-02 음수 방지: 차감 후 잔액이 음수가 되면 거부하고 데이터를 변경하지 않는다.
- AC-03 멱등성: 동일 요청 식별자 재요청은 기존 결과를 반환하고 중복 조정하지 않는다.

#### US-ADM-REWARD-003 Energy 수동 조정 [P0]

> 권한 있는 운영 관리자로서 광고·채팅 보상 문제를 정정하기 위해 회원의 Energy를 수동으로 지급하거나 차감할 수 있다.

- AC-01 상한 적용: 최대 Energy 초과 지급 시 요청량, 실제 지급량, 상한 적용 결과를 원장에 기록한다.
- AC-02 예약 보호: 채팅 예약 Energy를 제외한 사용 가능 Energy만 차감한다.
- AC-03 원자성: 지갑, Energy 원장, 감사 로그를 함께 저장한다.

#### US-ADM-REWARD-004 채널별 보상 조회 [P1]

> 운영 관리자로서 보상 채널의 정상 동작을 확인하기 위해 채널별 지급·거절 내역을 조회할 수 있다.

- AC-01 채널 구분: 출석, 광고, 오퍼월, 채팅, 초대, 룰렛을 구분한다.
- AC-02 상태 검색: 지급, 거절, 처리 중, 실패 상태와 기간으로 검색한다.
- AC-03 원본 추적: 원본 이벤트부터 자산 원장까지 처리 단계를 연결한다.

#### US-ADM-REWARD-005 실패 보상 재처리 [P1]

> 권한 있는 운영 관리자로서 보상 누락을 안전하게 복구하기 위해 재처리 가능한 보상을 다시 처리할 수 있다.

- AC-01 가능 여부: 원본 유효성, 기존 지급, 멱등 키 검사 결과를 반환한다.
- AC-02 안전한 재처리: 원본이 유효하고 지급 거래가 없으면 기존 비즈니스 규칙으로 한 번만 지급한다.
- AC-03 무효 이벤트 차단: 위조 서명, 미존재 회원, 기지급 거래는 거부하고 근거를 기록한다.

### 7.6 광고·오퍼월

#### US-ADM-AD-001 AdMob SSV 이력 조회 [P0]

> 운영·CS 관리자로서 광고 보상 누락의 원인을 확인하기 위해 AdMob SSV 처리 이력을 조회할 수 있다.

- AC-01 검색: 거래 ID, 회원, 광고 단위, 보상 상태, 기간으로 검색해 최신순 반환한다.
- AC-02 단계 표시: 서명, 광고 단위, timestamp, nonce, 일일 한도, 지급 결과를 단계별로 표시한다.
- AC-03 회원 연결: 원본 SSV 이벤트, nonce, 회원, Energy 원장 거래를 연결한다.

#### US-ADM-AD-002 광고 시청·한도 조회 [P1]

- AC-01 일일 현황: 특정 KST 날짜의 사용 횟수, 일일 한도, 남은 횟수, 리셋 시각을 반환한다.
- AC-02 시청 기록: 성공, 실패, 거절 사유, 실제 지급 Energy를 표시한다.
- AC-03 한도 정합성: quota 사용 횟수와 지급 처리 건수의 정책상 일치 여부를 표시한다.

#### US-ADM-AD-003 TNK 오퍼월 이력 조회 [P1]

> 운영·CS 관리자로서 오퍼월 적립 문제를 조사하기 위해 TNK 포스트백과 지급 이력을 조회할 수 있다.

- AC-01 검색: 플랫폼, 거래 ID, 회원, 상태, 기간으로 검색한다.
- AC-02 검증·지급 연결: 체크섬 검증, 사용자 토큰 해석, 원본 금액, 환산 포인트, 원장 거래를 표시한다.
- AC-03 중복 판정: 최초 처리와 중복 수신 이력을 구분한다.

#### US-ADM-AD-004 광고·오퍼월 운영 정책 [P2]

> 운영 관리자로서 수익성과 보상 정책을 조정하기 위해 광고·오퍼월의 운영 값을 관리할 수 있다.

- AC-01 정책 관리: 광고 활성 여부, 일일 한도, Energy 지급량, 오퍼월 환산비 변경 시 유효 시각부터 서비스 서버가 적용한다.
- AC-02 검증: 손실·비정상 지급 유발 값은 허용 범위·이익 가드 검증으로 거부한다.
- AC-03 변경 이력: 전후 값, 적용 기간, 처리자, 사유를 반환한다.

#### US-ADM-AD-005 광고 콘텐츠 노출 관리 [P2]

> 운영 관리자로서 장애나 캠페인 상황에 대응하기 위해 광고·오퍼월 노출을 관리할 수 있다.

- AC-01 채널 활성화: 플랫폼별 활성 상태 변경 시 앱이 다음 설정 갱신부터 반영한다.
- AC-02 placement 관리: 광고 단위 ID·노출 위치를 환경·플랫폼별 값 검증 후 적용한다.
- AC-03 긴급 중지: 신규 진입을 차단하고 기존 거래 이력은 보존한다.

### 7.7 채팅·AI 운영

#### US-ADM-CHAT-001 채팅 이력 조회 [P1]

> 운영·CS 관리자로서 채팅 문의의 원인을 조사하기 위해 회원의 대화와 메시지 이력을 조회할 수 있다.

- AC-01 대화 검색: 회원, 대화 ID, 메시지 상태, 모델, 기간으로 검색해 페이징 반환한다.
- AC-02 메시지 상태: 역할, 상태, 모델, 발생 시각을 순서대로 반환한다.
- AC-03 원문 보호: 채팅 원문 권한이 없으면 내용은 제외하고 운영 메타데이터만 반환한다.

#### US-ADM-CHAT-002 채팅 성공·실패 분석 [P1]

> 운영 관리자로서 채팅 품질 저하를 파악하기 위해 요청의 성공·실패 현황을 조회할 수 있다.

- AC-01 상태 집계: 전체 요청, 정상 완료, 스트리밍 실패, 취소를 구분한다.
- AC-02 모델별 분석: 모델별 요청 수, 성공률, 실패율을 반환한다.
- AC-03 자산 처리 연결: 메시지 상태와 관련 Energy·포인트·경험치 거래를 연결한다.

#### US-ADM-CHAT-003 AI 토큰·비용 기록 [P1]

> 비용 관리자로서 정확한 AI 비용을 계산하기 위해 채팅 요청별 토큰 사용량과 비용 기준을 조회할 수 있다.

- AC-01 사용량 저장: 채팅 요청 종료 시 모델, 입력·출력·합계 토큰, 요청 상태를 저장한다.
- AC-02 비용 단가: 요청 시점에 유효한 단가를 적용한다.
- AC-03 미확정 비용: usage·단가 정보가 없으면 0으로 오인하지 않도록 미집계 상태로 표시한다.

#### US-ADM-CHAT-004 AI 모델 라우팅 정책 [P2]

> 운영 관리자로서 품질과 비용의 균형을 조정하기 위해 AI 모델 라우팅 정책을 관리할 수 있다.

- AC-01 정책 변경: 티어별 활성 상태, 확률, 일일 cap 변경 시 유효 시각부터 적용한다.
- AC-02 합계 검증: 확률 합계와 허용 범위를 검증한다.
- AC-03 롤백: 새 변경 버전으로 이전 값을 재적용하고 이력을 보존한다.

#### US-ADM-CHAT-005 품질 풀 운영 [P2]

> 운영 관리자로서 프리미엄 AI 사용 재원을 통제하기 위해 공용 품질 풀과 회원별 사용량을 조회할 수 있다.

- AC-01 풀 잔액: 현재 잔액, 기간별 적립·소비, 프리미엄 요청 수를 반환한다.
- AC-02 회원별 cap: 사용 횟수, cap, 강등 여부를 반환한다.
- AC-03 이상 경고: 잔액·소비량 임계치 초과 시 부족·급증 경고를 표시한다.

### 7.8 상점·주문

#### US-ADM-SHOP-001 상품 관리 [P2]

> 운영 관리자로서 판매 카탈로그를 운영하기 위해 상품을 등록·수정·비활성화할 수 있다.

- AC-01 상품 등록: 상품 코드, 이름, 설명, 이미지, 카테고리, 가격, 노출 순서를 입력하면 중복되지 않은 상품을 비활성 초안으로 생성한다.
- AC-02 판매 활성화: 필수 정보·재고 정책이 유효하면 서비스 카탈로그에 노출한다.
- AC-03 삭제 제한: 주문·인벤토리 이력이 있는 상품은 물리 삭제를 거부하고 비활성화만 허용한다.

#### US-ADM-SHOP-002 재고·판매 정책 관리 [P2]

> 운영 관리자로서 품절과 과판매를 방지하기 위해 상품 재고와 판매 조건을 관리할 수 있다.

- AC-01 재고: 재고 원장과 현재 수량을 단일 트랜잭션으로 변경한다.
- AC-02 판매 조건: 판매 기간·회원별 구매 제한을 설정하고 구매 시점에 재검증한다.
- AC-03 동시 구매: 재고보다 많은 주문이 완료되지 않는다.

#### US-ADM-SHOP-003 주문 조회 [P1]

> 운영·CS 관리자로서 구매 문의와 장애를 처리하기 위해 주문 내역을 조회할 수 있다.

- AC-01 검색: 주문 ID, 회원, 상품, 상태, 기간으로 검색해 최신순 반환한다.
- AC-02 주문 상세: 가격 스냅샷, 수량, 포인트 거래, 지급 아이템, 상태 이력을 반환한다.
- AC-03 실패 식별: 실패 단계와 재처리 가능 여부를 표시한다.

#### US-ADM-SHOP-004 주문 취소·복구 [P2]

> 권한 있는 운영 관리자로서 주문 오류를 정정하기 위해 주문을 취소하거나 지급을 복구할 수 있다.

- AC-01 취소 가능 여부: 주문 상태, 아이템 사용 여부, 환불 이력을 검증한다.
- AC-02 원자적 취소: 아이템 회수, 포인트 환불, 주문 상태, 감사 로그를 함께 처리한다.
- AC-03 중복 취소 방지: 이미 취소된 주문은 기존 결과를 반환하고 추가 환불하지 않는다.

#### US-ADM-SHOP-005 교환 상품·발송 관리 [P3]

> 운영 관리자로서 기프티콘과 교환 상품을 안정적으로 제공하기 위해 공급업체와 발송 상태를 관리할 수 있다.

- AC-01 공급 정보: 공급업체, 공급 상품 코드, 유효기간 정책을 등록하고 민감 인증 정보는 암호화 저장한다.
- AC-02 발송 상태: 요청, 성공, 실패, 재시도 상태와 외부 거래 ID를 기록한다.
- AC-03 실패 재처리: 같은 외부 멱등 키로 중복 발송 없이 처리한다.

### 7.9 진화·리텐션 콘텐츠

#### US-ADM-CONTENT-001 진화 정책 관리 [P2]

> 운영 관리자로서 성장 난이도와 보상을 조정하기 위해 진화 등급 정책을 관리할 수 있다.

- AC-01 등급 규칙: 필요 경험치, 기본 성공률, 실패 결과 변경 시 허용 범위와 레벨 연결을 검증한다.
- AC-02 적용 시점: 유효 시각 도래 시 새 진화 시도부터 적용한다.
- AC-03 이력: 특정 시도 상세에 당시 적용 정책 버전을 표시한다.

#### US-ADM-CONTENT-002 진화 이력 조회 [P1]

> 운영·CS 관리자로서 진화 문의를 조사하기 위해 회원의 진화 상태와 시도 이력을 조회할 수 있다.

- AC-01 상태 조회: 현재 레벨, 경험치, 다음 시도 비용을 표시한다.
- AC-02 시도 이력: 전후 레벨, 비용, 기본·최종 성공률, 타이밍 등급, 결과를 반환한다.
- AC-03 정책 연결: 계산 근거를 재현할 수 있도록 정책 값을 표시한다.

#### US-ADM-CONTENT-003 출석·초대·룰렛 정책 [P2]

> 운영 관리자로서 리텐션 보상을 조정하기 위해 출석·초대·룰렛 정책을 관리할 수 있다.

- AC-01 출석 정책: 중복 일차와 음수 보상을 거부한다.
- AC-02 초대 정책: 신규 redeem부터 새 버전을 적용한다.
- AC-03 룰렛 정책: 확률 합계와 지급 상한을 검증한다.

### 7.10 공지·약관·고객지원

#### US-ADM-NOTICE-001 공지사항 관리 [P1]

> 운영 관리자로서 서비스 정보를 전달하기 위해 공지사항을 작성·예약·종료할 수 있다.

- AC-01 작성·예약: 제목, 내용, 노출 기간, 플랫폼, 중요도를 입력해 초안·예약 상태로 저장한다.
- AC-02 사용자 노출: 노출 조건에 맞는 게시 상태 공지만 반환한다.
- AC-03 수정 이력: 버전별 내용, 처리자, 시각을 반환한다.

#### US-ADM-NOTICE-002 약관 개정 관리 [P2]

> 운영 관리자로서 법적 고지와 동의 이력을 관리하기 위해 약관 버전을 등록하고 시행할 수 있다.

- AC-01 버전 등록: 버전, 본문, 시행일, 재동의 여부를 입력해 중복 없는 버전을 생성한다.
- AC-02 시행: 시행일 도래 시 유효 버전을 반환한다.
- AC-03 동의 추적: 회원, 버전, 동의 시각, 근거를 기록한다.

#### US-ADM-CS-001 문의·VoC 관리 [P1]

> CS 관리자로서 고객 요청의 누락을 방지하기 위해 문의와 고객의 소리를 접수·분류·배정할 수 있다.

- AC-01 접수: 제목, 내용, 분류 제출 시 접수 번호와 접수 상태를 생성한다.
- AC-02 배정·상태: 담당자·우선순위 지정 시 처리 상태와 담당자를 변경하고 이력을 남긴다.
- AC-03 운영 데이터 연결: 관련 광고·보상·주문 거래를 연결해 문의 상세에서 조회할 수 있다.

#### US-ADM-CS-002 문의 답변·처리 이력 [P1]

> CS 관리자로서 일관된 고객 응대를 위해 문의 답변과 처리 이력을 관리할 수 있다.

- AC-01 답변: 작성자, 시각, 발송 상태, 본문을 기록한다.
- AC-02 내부 메모 분리: 내부 메모는 사용자에게 노출하지 않는다.
- AC-03 완료: 완료 사유와 연결된 보상·주문 조정을 보존한다.

#### US-ADM-OPS-001 앱 버전·서비스 설정 [P2]

> 운영 관리자로서 안전한 앱 운영을 위해 최소 지원 버전과 서비스 설정을 관리할 수 있다.

- AC-01 버전 정책: 최신·최소 지원 버전과 강제 업데이트 여부를 설정하면 앱 게이트가 플랫폼·버전별 정책을 반환한다.
- AC-02 점검 모드: 기간·안내 문구 설정 시 허용된 예외 기능 외 진입을 제한한다.
- AC-03 예약·이력: 유효 시각 도래 시 새 버전을 적용하고 이전 값을 보존한다.

#### US-ADM-OPS-002 푸시 알림 발송 [P2]

> 운영 관리자로서 대상 회원에게 운영·마케팅 정보를 전달하기 위해 푸시 알림을 예약·발송할 수 있다.

- AC-01 대상 미리보기: 발송 전 예상 대상 수와 제외 사유를 표시한다.
- AC-02 예약 발송: 예약 시각 도래 시 중복 발송 없이 발송 작업을 생성한다.
- AC-03 결과: 성공, 실패, 무효 토큰, 재시도 수를 반환한다.

### 7.11 서버·배포 운영

#### US-ADM-SERVER-001 서비스 상태 조회 [P0]

> 운영 관리자로서 장애 여부를 빠르게 판단하기 위해 서비스 서버와 주요 의존성의 상태를 조회할 수 있다.

- AC-01 상태 확인: 서비스, DB, 외부 AI, 필수 연동의 정상·비정상 상태와 확인 시각을 표시한다.
- AC-02 타임아웃: 제한 시간 내 무응답 시 장애 상태로 표시하되 관리자 화면 전체 요청은 실패시키지 않는다.
- AC-03 이력: 장애 시작·복구 시각과 지속 시간을 반환한다.

#### US-ADM-SERVER-002 오류·응답시간 조회 [P1]

> 운영 관리자로서 장애 원인을 조사하기 위해 서버 오류율, 응답시간과 오류 로그를 조회할 수 있다.

- AC-01 메트릭: API별 요청 수, 오류율, 응답시간 백분위를 반환한다.
- AC-02 오류 검색: 추적 ID, API, 오류 종류, 기간으로 검색하고 민감정보를 마스킹한다.
- AC-03 운영 데이터 연결: 권한 범위 안에서 관련 운영 데이터로 이동한다.

#### US-ADM-SERVER-003 배포·재기동 요청 [P3]

> 권한 있는 운영 관리자로서 장애 복구를 위해 승인된 배포 파이프라인의 재기동 작업을 요청할 수 있다.

- AC-01 파이프라인 호출: 허용된 파이프라인만 최소 권한 자격증명으로 호출한다.
- AC-02 이중 확인: 프로덕션 재기동 시 대상 환경과 예상 영향을 재확인한다.
- AC-03 상태 추적: 요청자, 외부 실행 ID, 진행 상태, 결과를 표시한다.

### 7.12 마케팅·매출·정산

#### US-ADM-MKT-001 마케팅 채널 비용 관리 [P3]

> 마케팅·분석 관리자로서 채널별 효율을 계산하기 위해 광고 캠페인 비용을 등록하고 조회할 수 있다.

- AC-01 비용 등록: 기간, 통화, 지출 금액 입력 또는 외부 데이터 수집 시 중복 기간·캠페인을 검증해 저장한다.
- AC-02 채널 구분: 채널·캠페인별 지출을 원화 환산값과 함께 반환한다.
- AC-03 변경 이력: 원본, 전후 값, 처리자, 사유를 반환한다.

#### US-ADM-MKT-002 유입·전환 분석 [P3]

> 마케팅·분석 관리자로서 사용자 획득 효율을 평가하기 위해 캠페인별 설치·가입·활성 전환을 조회할 수 있다.

- AC-01 귀속 데이터: 설치, 가입, 활성 회원, 전환율을 반환한다.
- AC-02 중복 제거: 정의된 귀속 모델에 따라 회원을 중복 집계하지 않는다.
- AC-03 CAC: 채널·캠페인별 CAC와 계산 기준을 표시한다.

#### US-ADM-MKT-003 유입 회원 수익 분석 [P3]

> 마케팅·분석 관리자로서 마케팅 수익성을 판단하기 위해 캠페인 유입 회원의 수익과 비용을 비교할 수 있다.

- AC-01 수익 귀속: 캠페인 유입 회원에서 발생한 수익을 기간별로 반환한다.
- AC-02 ROI·ROAS: 계산식과 함께 표시한다.
- AC-03 미확정 표시: 예상 수익과 확정 수익을 구분한다.

#### US-ADM-FIN-001 서비스 수익 현황 [P2]

> 경영·분석 관리자로서 서비스 수익성을 파악하기 위해 광고·오퍼월 수익과 AI 비용을 조회할 수 있다.

- AC-01 수익원별 조회: AdMob, TNK와 향후 수익원을 구분해 총수익을 반환한다.
- AC-02 비용 비교: 수익, AI 비용, 마케팅 비용, 추정 기여이익을 표시한다.
- AC-03 데이터 신뢰도: 값별 출처와 확정 여부를 표시한다.

#### US-ADM-FIN-002 정산 내역 조회 [P3]

> 재무 관리자로서 수익 배분과 보상 부채를 검증하기 위해 정산 내역을 조회할 수 있다.

- AC-01 Ledger 상태 명시: 휴면·미연결 상태를 명확히 표시하고 실제 수익으로 합산하지 않는다.
- AC-02 연결 후 정산: 총수익, 위험 준비금, 서비스 준비금, 사용자 보상, 회사 이익을 반환한다.
- AC-03 대조: 광고사 확정 리포트와 내부 지급 데이터의 차이 금액과 원인 후보를 표시한다.

### 7.13 어뷰징·위험 관리

#### US-ADM-RISK-001 이상 적립 후보 조회 [P2]

> 운영 관리자로서 보상 손실을 줄이기 위해 비정상 적립 의심 회원을 조회할 수 있다.

- AC-01 규칙 탐지: 단시간 대량 적립, 동일 기기 다계정, 반복 실패 패턴에서 규칙, 근거 이벤트, 위험 점수를 가진 후보를 생성한다.
- AC-02 조사 상태: 정상, 조사 중, 확정 분류와 근거를 보존한다.
- AC-03 자동 제재 금지: 관리자 검토 전 자동 포인트 몰수·영구 정지를 수행하지 않는다.

#### US-ADM-RISK-002 기기·앱 식별자 차단 [P3]

> 권한 있는 운영 관리자로서 반복적인 악성 이용을 차단하기 위해 기기 또는 앱 식별자를 차단할 수 있다.

- AC-01 차단 등록: 식별자, 기간, 사유 입력 시 차단 목록에 등록하고 영향 회원을 표시한다.
- AC-02 서비스 적용: 차단 식별자의 신규 가입·인증 요청을 서비스 서버가 정책에 따라 거부한다.
- AC-03 해제·감사: 과거 기록을 보존하고 변경을 감사한다.

### 7.14 국제화

#### US-ADM-I18N-001 다국어 콘텐츠 관리 [P3]

> 운영 관리자로서 국가·언어별 사용자에게 적절한 정보를 제공하기 위해 운영 콘텐츠의 번역을 관리할 수 있다.

- AC-01 번역 등록: 공지·약관·상품의 기준 언어 콘텐츠 버전과 번역 버전을 연결한다.
- AC-02 폴백: 요청 언어 번역이 없으면 기본 언어 콘텐츠를 반환한다.
- AC-03 게시 검증: 필수 지원 언어 번역 누락 시 누락 언어를 표시하고 정책에 따라 게시를 차단한다.

#### US-ADM-I18N-002 국가·통화별 지표 [P3]

> 마케팅·분석 관리자로서 지역별 성과를 비교하기 위해 국가·언어·통화 기준의 지표를 조회할 수 있다.

- AC-01 지역 분류: 회원, 사용량, 수익, 비용을 지역 기준으로 반환한다.
- AC-02 통화 환산: 원통화와 기준통화 환산값, 적용 환율일을 표시한다.
- AC-03 개인정보 보호: 최소 익명성 기준 미만 집계는 숨기거나 상위 지역으로 합산한다.

## 10. 비기능 요구사항

- 관리자 API는 서비스 API와 별도 도메인·배포·인증 키를 사용한다.
- 운영 DB 연결은 TLS를 사용하고 비밀값을 소스 코드에 저장하지 않는다.
- 민감한 관리자 API에는 속도 제한과 네트워크 접근 정책을 적용한다.
- 목록·통계 쿼리는 인덱스와 실행 계획을 검증하고 서비스 트랜잭션을 장시간 잠그지 않는다.
- 대량 다운로드는 비동기 작업으로 만들고 만료되는 다운로드 링크를 사용한다.
- 감사 로그와 자산 원장은 보존 기간과 백업·복구 절차를 별도로 정의한다.
- 시간 기준은 KST로 통일하고 저장 시각은 UTC `Instant`로 보존한다.
- 관리자 서버 장애가 서비스 앱의 핵심 요청을 중단시키지 않아야 한다.
- 관리자 변경 API는 정상, 권한 부족, 중복 요청, 동시 충돌, 부분 실패를 테스트한다.

## 11. 범위 밖 또는 선행 결정이 필요한 사항

- 사용자 현금 출금·환전은 현재 서비스에 없으므로 본 관리자 시스템의 초기 범위가 아니다.
- 휴면 Ledger를 광고·오퍼월에 연결할지는 별도 회계 정책 결정이 필요하다.
- 마케팅 ROI에는 외부 광고 플랫폼의 비용·어트리뷰션 데이터 연동 방식 결정이 필요하다.
- 서버 재기동은 임의 셸 실행이 아니라 사전에 등록된 CI/CD 파이프라인 호출만 허용한다.
- 자동 몰수·영구 제재는 오탐 위험 때문에 초기 어뷰징 탐지 범위에서 제외한다.
