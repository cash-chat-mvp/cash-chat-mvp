## 1. 배경

AI 챗봇의 캐릭터 레벨이 오르면 더 좋은 모델이 나올 확률이 열린다. 이 구조는 리텐션에는 좋지만, 고레벨 유저가 오래 사용할수록 LLM 비용이 반복해서 발생한다.

따라서 진화 비용만으로 고급 모델 사용 비용을 모두 회수하려고 하면 안 된다. 진화 비용은 1회성 수익이고, 모델 비용은 사용량에 비례하는 반복 비용이기 때문이다.

이번 문서는 다음 목표를 가진다.

- 유저에게는 "레벨이 오를수록 같은 사용 경험에서 더 좋은 답변 확률을 얻는다"는 효용을 제공한다.
- 회사는 광고/포인트 수익 중 일부를 고급 답변 경험에 재투자해 충성 고객을 확보한다.
- 단, 고레벨 유저가 오래 사용해도 미회수 LLM 비용이 무한히 커지지 않도록 한다.

## 2. 설계 원칙

1. `1pt = 1원`으로 계산한다.
2. 레벨은 고급 모델 확률을 "해금"한다.
3. 포만도는 해금된 확률을 실제로 켜는 기본 연료다.
4. 퀄리티 버젯은 mini/gpt 호출의 추가 비용을 감당하는 개인별 예산이다.
5. 광고 수익은 유저 포인트, 서비스 유지비, 회사 이익, 퀄리티 버젯으로 나눠 기록한다.
6. 고레벨 유저는 회사 이익률이 낮아질 수 있지만, 충성 고객 확보를 위해 일부 마진을 고급 답변 경험에 재투자한다.
7. 고레벨 유저라도 퀄리티 버젯이 부족하면 `nano-only` 또는 낮은 라우팅으로 내려간다.
8. `pro` 모델은 MVP 범위에서 사용하지 않는다.

## 3. 핵심 용어

| 용어 | 설명 |
| --- | --- |
| `displayLevel` | 유저가 진화로 달성한 캐릭터 레벨. UI에 표시되는 레벨 |
| `effectiveLevel` | 포만도, 퀄리티 버젯, 광고 cap, 비용 상태를 반영해 실제 모델 라우팅에 사용하는 레벨 |
| `satiety` | 포만도. 고급 라우팅을 켜기 위해 메시지마다 소모되는 연료 |
| `qualityBudget` | 개인별 고급 모델 예산. nano보다 비싼 모델을 호출할 때 추가 비용만큼 차감 |
| `costDebt` | 실제 LLM 비용 중 아직 회수하지 못한 비용 |
| `companyProfitReserve` | 광고/포인트 수익 중 회사 이익으로 먼저 확보하는 금액 |
| `serviceMaintenanceReserve` | 서버, 운영, 정산 리스크 등 서비스 유지 비용으로 확보하는 금액 |

## 4. 모델 라우팅

### 4.1 모델 풀

| 등급 | 모델 | 역할 |
| --- | --- | --- |
| nano | GPT nano | 기본 답변. 공복, cap 초과, budget 부족 시 fallback |
| mini | GPT mini | 중간 품질 답변. Lv2부터 확률 해금 |
| gpt | GPT | 고급 답변. Lv4부터 낮은 확률로 해금 |
| pro | 사용 안 함 | 비용 리스크로 제외 |

### 4.2 레벨별 최대 라우팅 확률

이 표는 "항상 보장되는 확률"이 아니라, 포만도와 퀄리티 버젯이 충분할 때 적용 가능한 최대 확률이다.

| Lv | nano | mini | gpt | 설명 |
| --- | ---: | ---: | ---: | --- |
| 1 | 100% | 0% | 0% | 기본 상태 |
| 2 | 95% | 5% | 0% | mini 확률 최초 해금 |
| 3 | 80% | 20% | 0% | mini 체감 강화 |
| 4 | 60% | 35% | 5% | gpt 확률 최초 해금 |
| 5 | 40% | 50% | 10% | 최상위 일반 라우팅 |

### 4.3 실제 라우팅 결정

```text
if satiety <= 0:
    effectiveLevel = 1
else if qualityBudget <= 0:
    effectiveLevel = 1
else if rewardedAdDailyCapReached and costDebt >= AD_GATE_REQUIRED_THRESHOLD:
    effectiveLevel = 1
else:
    effectiveLevel = displayLevel
```

`effectiveLevel = 1`이면 `nano-only`로 답변한다. 캐릭터 레벨 자체는 떨어지지 않는다.

## 5. 포만도 정책

포만도는 고급 라우팅을 켜는 기본 연료다. 레벨이 오를수록 메시지당 포인트가 계속 오르면 고레벨 효용이 떨어지므로, MVP에서는 모든 레벨의 메시지당 포만도 소모를 고정한다.

| 항목 | 값 | 설명 |
| --- | ---: | --- |
| 메시지 1회 포만도 소모 | 5pt | Lv2~Lv5 공통 |
| 포만도 충전 방식 | 슬라이드 바 | 유저가 원하는 양만큼 포인트를 넣어 충전 |
| 최소 충전 단위 | 5pt | 메시지 1회분 |
| 권장 충전 단위 | 5pt 단위 | 5pt, 10pt, 15pt, 20pt... |

유저 관점에서는 다음처럼 이해하게 한다.

```text
포만도 5pt = 채팅 1회 동안 고급 답변 확률 활성화
슬라이드 바로 원하는 만큼 포만도를 충전
```

고레벨 유저도 메시지 1회당 같은 5pt를 쓰지만, 레벨이 높을수록 더 좋은 최대 확률을 얻는다. Lv5에서도 기본 비용은 5pt로 동일하게 두고, gpt/mini 추가 비용은 퀄리티 버젯과 Ad Gate로 방어한다.

진화 성공 직후에는 1회만 포만도를 50%까지 보정한다.

```text
satiety = max(currentSatiety, maxSatiety * 0.5)
```

자동 회복은 두지 않는다.

```text
가입 최초 1회: satiety 50% 허용
진화 성공 직후 1회: satiety 50% 보정
매일 자동 회복: 없음
공복 상태: displayLevel 유지, effectiveLevel = Lv1
```

## 6. 진화 비용

진화는 확률형 시도이므로 성공 1회를 만들기 위한 기대 지불액은 다음과 같다.

```text
성공 1회 기대 지불액 = 시도 비용 / 성공 확률
```

예를 들어 시도 비용이 500pt이고 성공 확률이 70%라면:

```text
500 / 0.7 = 약 714pt
```

| 진화 | 성공률 | 시도 비용 | 성공 1회 기대 지불액 |
| --- | ---: | ---: | ---: |
| Lv1 -> Lv2 | 70% | 500pt | 약 714pt |
| Lv2 -> Lv3 | 50% | 1,200pt | 2,400pt |
| Lv3 -> Lv4 | 25% | 3,000pt | 12,000pt |
| Lv4 -> Lv5 | 10% | 8,000pt | 80,000pt |

진화 비용은 고급 모델을 무제한으로 보장하는 비용이 아니다. 고급 모델 확률을 해금하고, 초기 퀄리티 버젯 일부를 확보하는 비용으로 본다.

## 7. 퀄리티 버젯

### 7.1 왜 필요한가

진화 비용은 1회성 수익이고, 고급 모델 비용은 메시지마다 반복해서 발생한다.

```text
누적 손익(N)
= 진화 수익
+ N * (밥값 + 광고 회수액 - 기대 LLM 비용)
```

만약 다음 조건이 깨지면, 고레벨 유저가 오래 사용할수록 언젠가는 적자가 된다.

```text
밥값 + 광고 회수액 >= 기대 LLM 비용
```

따라서 mini/gpt 호출은 반드시 개인별 `qualityBudget` 안에서만 허용한다.

### 7.2 차감 방식

nano는 기본 모델이므로 추가 비용을 만들지 않는 기준선으로 둔다. mini/gpt가 선택되면 nano 대비 추가 비용만큼 퀄리티 버젯을 차감한다.

```text
모델 추가 비용 = 선택된 모델 비용 - nano 비용
qualityBudget = qualityBudget - max(0, 모델 추가 비용)
```

퀄리티 버젯이 부족하면 gpt 또는 mini 확률을 줄이고, 최종적으로 `nano-only`로 내려간다.

```text
if qualityBudget >= gptDeltaCost:
    Lv별 최대 라우팅 사용 가능
else if qualityBudget >= miniDeltaCost:
    gpt 확률 제거, mini까지만 사용
else:
    nano-only
```

### 7.3 적립처

퀄리티 버젯은 다음 수익에서 일부를 적립한다.

| 적립처 | 설명 |
| --- | --- |
| 진화 시도 비용 일부 | 고급 확률 해금에 대한 선불 재원 |
| 밥값 중 일부 | nano 원가와 운영비를 뺀 일부 |
| Ad Gate 광고 순수익 일부 | 답변 언락 광고에서 남는 금액 |
| 혜택존 광고 순수익 일부 | 유저 포인트 지급 후 남는 금액 |
| 포인트 직접 충전 일부 | 충전 상품 마진 중 일부 |
| 쿠팡 커미션 일부 | 쇼핑 큐레이션 수익 일부 |

## 8. 광고 수익 분배

광고 수익 전체를 유저 포인트로 지급하거나 퀄리티 버젯으로 넣으면 회사 이익이 사라진다. 반대로 회사 이익을 너무 많이 가져가면 고레벨 효용이 약해진다.

따라서 광고 1회 수익은 다음 순서로 나눈다.

```text
광고 순수익
= 광고 총수익
- 무효 트래픽/정산 리스크 예비금
```

```text
광고 순수익
= 유저 포인트 보상
+ 서비스 유지 비용
+ 회사 이익
+ 퀄리티 버젯 적립액
```

팀원이 이해하기 쉽게 풀면:

1. 광고에서 들어온 돈에서 무효 트래픽, 정산 지연, 국가별 단가 차이 같은 리스크를 먼저 뺀다.
2. 유저에게 약속한 포인트 보상을 지급한다.
3. 서버와 운영 유지 비용을 먼저 확보한다.
4. 회사가 최소로 가져가야 하는 이익을 확보한다.
5. 남는 금액을 해당 유저의 퀄리티 버젯에 적립한다.

공식으로 쓰면:

```text
회사 이익으로 먼저 확보할 금액
= 고정 최소 이익과 광고 순수익의 최소 이익률 중 더 큰 값
```

```text
퀄리티 버젯 적립액
= 광고 순수익
- 유저 포인트 보상
- 서비스 유지 비용
- 회사 이익
```

예시:

| 항목 | 금액 |
| --- | ---: |
| 광고 총수익 | 12pt |
| 리스크 예비금 | -2pt |
| 광고 순수익 | 10pt |
| 유저 포인트 보상 | -3pt |
| 서비스 유지 비용 | -2pt |
| 회사 이익 | -2pt |
| 퀄리티 버젯 적립 | 3pt |

고레벨 유저는 회사 이익 비중을 조금 낮추고 퀄리티 버젯 비중을 높일 수 있다. 이는 즉시 이익률을 낮추는 대신 충성 고객의 리텐션에 재투자하는 정책이다.

단, 회사 이익은 0이 되면 안 된다.

```text
회사 이익 >= 광고 순수익 * 최소 이익률
```

## 9. Ad Gate 빈도와 cap

광고는 고정 주기마다 뜨는 것이 아니라 `costDebt`와 `qualityBudget` 상태를 보고 뜬다.

```text
if costDebt < 15pt:
    광고 없음

if 15pt <= costDebt < 30pt:
    광고 후보

if costDebt >= 30pt:
    광고 또는 포인트 언락 필요
```

광고 후보 구간의 확률:

```text
광고 확률 = ((costDebt - 15) / 15) * 0.5
```

| costDebt | 광고 확률 |
| ---: | ---: |
| 0~14pt | 0% |
| 20pt | 약 17% |
| 25pt | 약 33% |
| 30pt 이상 | 100% |

광고 간격:

```text
마지막 광고 후 최소 5분
마지막 광고 후 최소 3개 메시지
일반 유저 하루 rewarded 광고 10회
신뢰 유저 하루 rewarded 광고 20회
위험 유저 하루 rewarded 광고 3~5회
```

광고 cap 이후에는 무료 고급 답변을 제공하지 않는다.

```text
if rewardedAdDailyCapReached:
    mini/gpt 라우팅 비활성화
    costDebt가 낮으면 nano-only 허용
    costDebt가 높으면 포인트 결제 필요
```

## 10. costDebt 손익 방어

각 메시지 후 실제 token usage 기준으로 비용을 계산한다.

```text
실제 LLM 비용 = 입력 토큰 비용 + 출력 토큰 비용
```

회수 금액:

```text
회수 금액
= 밥값
+ 포인트 언락 결제액
+ 검증된 광고 순수익 중 비용 회수분
+ 쿠팡 커미션 중 비용 회수분
```

미회수 비용:

```text
costDebt = max(0, costDebt + 실제 LLM 비용 - 회수 금액)
```

핵심 불변식:

```text
costDebt <= HARD_STOP_THRESHOLD
```

이를 유지하기 위한 정책:

```text
if costDebt >= HARD_STOP_THRESHOLD:
    포인트 결제 전 답변 생성 중단
```

즉 이 설계는 모든 메시지가 항상 즉시 흑자임을 보장하는 방식이 아니다. 대신 미회수 비용의 최대치를 제한하고, 그 이상은 광고/포인트 없이 LLM 비용이 더 발생하지 않도록 차단한다.

## 11. Lv별 채팅 1회 예상 손익

### 11.1 계산 가정

아래 계산은 실제 운영 단가가 아니라 MVP 기획 검증용 가정이다. 실제 구현에서는 모델별 token usage와 환율을 서버에서 기록해 매일 재계산한다.

| 항목 | 가정 |
| --- | ---: |
| 평균 입력 토큰 | 1,000 tokens |
| 평균 출력 토큰 | 1,000 tokens |
| 환율 | 1달러 = 1,500원 |
| 포인트 가치 | 1pt = 1원 |
| Lv1 밥값 | 0pt/msg |
| Lv2~Lv5 밥값 | 5pt/msg |

OpenAI 공개 API 가격 기준:

| 모델 | 입력 단가 | 출력 단가 |
| --- | ---: | ---: |
| GPT nano | $0.05 / 1M tokens | $0.40 / 1M tokens |
| GPT mini | $0.25 / 1M tokens | $2.00 / 1M tokens |
| GPT | $1.25 / 1M tokens | $10.00 / 1M tokens |

모델별 1회 채팅 예상 원가는 다음과 같다.

```text
모델 1회 원가
= (입력 토큰 / 1,000,000 * 입력 단가
 + 출력 토큰 / 1,000,000 * 출력 단가)
 * 환율
```

| 모델 | 1회 예상 원가 |
| --- | ---: |
| GPT nano | 약 0.68pt |
| GPT mini | 약 3.38pt |
| GPT | 약 16.88pt |

### 11.2 Lv별 기대 LLM 비용

```text
Lv별 기대 LLM 비용
= nano 확률 * nano 원가
+ mini 확률 * mini 원가
+ gpt 확률 * gpt 원가
```

| Lv | nano | mini | gpt | 기대 LLM 비용/msg |
| --- | ---: | ---: | ---: | ---: |
| 1 | 100% | 0% | 0% | 약 0.68pt |
| 2 | 95% | 5% | 0% | 약 0.81pt |
| 3 | 80% | 20% | 0% | 약 1.22pt |
| 4 | 60% | 35% | 5% | 약 2.43pt |
| 5 | 40% | 50% | 10% | 약 3.65pt |

### 11.3 레벨별 평균 메시지 비용

레벨별 평균 메시지 비용은 "해당 레벨에서 모델이 확률적으로 섞여 나올 때, 채팅 1회당 회사가 부담하는 평균 LLM 원가"다.

```text
평균 메시지 비용
= nano 사용률 * nano 1회 원가
+ mini 사용률 * mini 1회 원가
+ gpt 사용률 * gpt 1회 원가
```

MVP에서는 Lv2~Lv5 모두 메시지 1회당 5pt를 소모한다.

| Lv | 모델 사용 비율 | 평균 메시지 비용 | 메시지당 포만도 수익 | 메시지당 잔여/부족 |
| --- | --- | ---: | ---: | ---: |
| 1 | nano 100% | 약 0.68pt | 0pt | -0.68pt |
| 2 | nano 95% + mini 5% | 약 0.81pt | 5pt | +4.19pt |
| 3 | nano 80% + mini 20% | 약 1.22pt | 5pt | +3.78pt |
| 4 | nano 60% + mini 35% + gpt 5% | 약 2.43pt | 5pt | +2.57pt |
| 5 | nano 40% + mini 50% + gpt 10% | 약 3.65pt | 5pt | +1.35pt |

표 해석:

- Lv1은 밥을 먹이지 않는 무료 기본 구간이므로 메시지 단위 비용이 발생한다. 이 구간은 온보딩/획득 비용으로 본다.
- Lv2~Lv5는 모든 레벨에서 메시지 1회당 5pt를 소모한다.
- 이 가정에서는 Lv5도 메시지당 평균 LLM 비용을 포만도 수익으로 커버한다.
- 다만 평균 토큰 수가 커지거나 GPT 호출 단가가 오르면 Lv4~Lv5의 잔여분이 빠르게 줄어든다.

### 11.4 Lv별 채팅 1회 기대 마진

```text
채팅 1회 기대 마진
= 메시지당 포만도 수익
- Lv별 기대 LLM 비용
```

| Lv | 메시지당 포만도 수익 | 기대 LLM 비용/msg | 기대 마진/msg |
| --- | ---: | ---: | ---: |
| 1 | 0pt | 약 0.68pt | 약 -0.68pt |
| 2 | 5pt | 약 0.81pt | 약 +4.19pt |
| 3 | 5pt | 약 1.22pt | 약 +3.78pt |
| 4 | 5pt | 약 2.43pt | 약 +2.57pt |
| 5 | 5pt | 약 3.65pt | 약 +1.35pt |

해석:

- Lv1은 무료 기본 경험이므로 메시지 단위로는 비용이 발생한다. 이 구간은 온보딩/획득 비용으로 본다.
- Lv2~Lv5는 메시지 1회당 같은 5pt를 쓰며, 레벨이 오를수록 더 좋은 모델 확률을 얻는다.
- Lv5도 평균적으로는 메시지당 기대 마진이 양수다.
- 이 마진 전체가 회사 이익은 아니다. 일부는 퀄리티 버젯으로 다시 적립해 고레벨 경험에 재투자한다.
- 단, 평균 토큰 수가 커지거나 GPT 호출 단가가 오르면 Lv4~Lv5의 마진이 빠르게 줄어든다.

### 11.5 퀄리티 버젯 예상 소모

퀄리티 버젯은 nano 대비 추가 비용만큼 차감한다.

```text
모델 추가 비용 = 선택된 모델 비용 - nano 비용
```

| 모델 | nano 대비 추가 비용 |
| --- | ---: |
| GPT nano | 0pt |
| GPT mini | 약 2.70pt |
| GPT | 약 16.20pt |

Lv별 평균 퀄리티 버젯 소모:

```text
Lv별 평균 퀄리티 버젯 소모
= mini 확률 * mini 추가 비용
+ gpt 확률 * gpt 추가 비용
```

| Lv | 평균 퀄리티 버젯 소모/msg |
| --- | ---: |
| 1 | 0pt |
| 2 | 약 0.14pt |
| 3 | 약 0.54pt |
| 4 | 약 1.76pt |
| 5 | 약 2.97pt |

즉 Lv5 유저가 채팅 1회를 할 때, 평균적으로 약 2.97pt의 퀄리티 버젯이 고급 모델 혜택에 사용된다. 메시지당 포만도 수익 5pt 중 LLM 원가를 제외한 일부를 퀄리티 버젯으로 다시 적립해 고레벨 경험을 유지한다.

### 11.6 손익 위험이 생기는 지점

Lv5 기준으로 밥값만으로 손익분기하려면 다음 조건을 만족해야 한다.

```text
Lv5 기대 LLM 비용 <= 메시지당 포만도 수익
```

현재 가정에서는:

```text
Lv5 기대 LLM 비용 = 약 3.65pt
메시지당 포만도 수익 = 5pt
```

따라서 Lv5도 평균적으로 메시지당 약 1.35pt가 남는다.

```text
5 - 3.65 = +1.35pt
```

하지만 이 여유분은 평균 토큰 사용량이 커지면 빠르게 사라진다. 다음과 같은 상황에서는 Ad Gate, 포인트 언락, 모델 확률 축소가 필요하다.

- 긴 답변으로 출력 토큰이 크게 증가하는 경우
- 대화 히스토리 누적으로 입력 토큰이 커지는 경우
- GPT 호출 비중을 높이는 A/B 테스트를 하는 경우
- 환율 또는 모델 단가가 상승하는 경우

운영 안전장치:

```text
if expectedLLMCostByRecentUsage >= foodCost:
    gpt 확률 축소
    mini 확률 축소
    Ad Gate 후보 기준 하향
    필요 시 nano-only fallback
```

## 12. 레벨별 사업 의미

| 구간 | 의미 | 회사 관점 |
| --- | --- | --- |
| Lv1~Lv2 | 수익성 안정 구간 | nano 중심이라 비용 낮음 |
| Lv3 | 균형 구간 | mini 체감은 주되 budget 관리 필요 |
| Lv4~Lv5 | 충성 고객 투자 구간 | 회사 이익률 일부를 줄이고 고급 답변 경험에 재투자 |

Lv5는 무제한 고급 모델 등급이 아니다.

```text
Lv5 = 고급 모델 확률 상한이 가장 높은 VIP 구간
```

실제 고급 모델 호출은 퀄리티 버젯과 광고/포인트 회수 상태 안에서만 허용한다.

## 15. 구현 시 주의사항

- 모델 선택은 반드시 백엔드에서만 한다.
- 클라이언트에 실제 모델명을 노출하지 않는다.
- 포만도 차감, 퀄리티 버젯 차감, 모델 선택은 원자적으로 처리한다.
- AdMob 보상 포인트는 SSV 검증 성공 후에만 지급한다.
- 광고 cap 이후에는 고급 모델 라우팅을 끈다.
- 퀄리티 버젯이 부족하면 캐릭터 레벨은 유지하되 실제 라우팅만 낮춘다.
- 모든 수치값은 서버 설정 또는 Remote Config로 분리해 운영 중 조정 가능해야 한다.
