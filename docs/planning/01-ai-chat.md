### 1.2 진화/강화 서브 화면 (Chat 탭 내부)

캐릭터 헤더 또는 우측 상단 🎯 아이콘 탭으로 진입. 풀스크린 모달.

│        [캐릭터 일러스트]          │

│                                  │
│  Lv.3 유년기                    │
│  ████████░░ EXP 80/100          │
│                                  │
│  ──── 진화 조건 ────             │
│  • EXP 100 이상                  │
│  • 진화석 ×3 보유                │
│  • 성공 확률: 35%                │
│                                  │
│  [   진화 시도   ]  (200코인)    │
│                                  │
│  ──── 보조 아이템 ────           │
│  • 확률 부적 +10%  (상점)        │

진화 시도 → 슬롯/룰렛 풀스크린 애니메이션 (Compose Multiplatform Animation, 약 3~5초) → 결과 모달.

### 1.3 진화 단계 (가설)

| Lv | 명칭 | 외형 컨셉 | 다음 단계 성공 확률 | 모델 라우팅 (premium 비율) |
| -- | ---- | --------- | ------------------- | -------------------------- |
| 1  | 알   | 작은 알   | → Lv2: 70%          | 0% (mini 100%)             |
| 2  | 부화 | 새끼 형태 | → Lv3: 50%          | 5%                         |
| 3  | 유년 | 귀여운 캐릭 | → Lv4: 25%        | 20%                        |
| 4  | 성장 | 멋진 형태 | → Lv5: 10%          | 50%                        |
| 5  | 궁극 | 완전체    | (최종)              | 80%                        |

> 단계 수는 추후 게임밸런스 시뮬레이션 후 확정. 5단계는 출발 기준.

### 1.4 캐릭터 외형 정책 — AI 생성 기반 페르소나 슬롯 + 액세서리 오버레이

**방향 결정**: 페르소나 슬롯(옵션 C) + 액세서리 오버레이(옵션 A) 하이브리드. 자산은 디자이너 외주가 아닌 **AI 이미지 생성**으로 제작.

#### 구조

```
[베이스 일러스트 — AI 생성, 사전 제작 자산]
   = 페르소나 클러스터 × 진화 단계 매트릭스

   ┌────────┬────────┬────────┬────────┬────────┐
   │ 클러스터│ Lv1 알 │ Lv2 부화│ Lv3 유년│ Lv4 성장│ Lv5 궁극│
   ├────────┼────────┼────────┼────────┼────────┼────────┤
   │ 차분한 │  🥚    │  🐣    │  📚🐱  │  ...   │  ...   │
   │ 독서가 │        │        │        │        │        │
   ├────────┼────────┼────────┼────────┼────────┼────────┤
   │ 활동가 │  🥚    │  🐣    │  ⚡🦊  │  ...   │  ...   │
   ├────────┼────────┼────────┼────────┼────────┼────────┤
   │  ...   │        │        │        │        │        │

[액세서리 오버레이 — AI 생성, 투명 PNG]
   = 채팅에서 추출한 보조 태그로 런타임 합성
   예: 안경 / 머플러 / 동반 펫 / 배경 소품
```

- **베이스**: 페르소나 클러스터(8~12개) × 진화 단계(5) = **약 50장** AI 생성 자산
- **오버레이**: 액세서리 30~50종 투명 PNG (Compose에서 레이어 합성)
- 유저는 가입/초반 채팅에서 페르소나 클러스터 자동 할당 → 진화 시 같은 클러스터의 다음 단계 일러스트 호출

#### 페르소나 클러스터 할당 플로우

```
가입 후 첫 N(=10)메시지 누적
  ↓
[Backend] LLM 분류기로 페르소나 클러스터 분류
  - 입력: 누적 메시지 + 가입 시 입력값 (선택)
  - 출력: cluster_id (1~12)
  ↓
유저 프로필에 cluster_id 저장 (이후 변경 불가, Phase 2에 "이미지 리롤" 유료 아이템 검토)
  ↓
액세서리는 채팅 누적되며 동적 추가
  - 채팅에 "고양이" 다회 언급 → 펫 액세서리 슬롯에 고양이 배정
  - 채팅에 "운동" 다회 언급 → 의상 슬롯에 운동복 배정
```

#### AI 자산 생성 워크플로 (운영 가이드)

| 단계 | 작업 |
| --- | --- |
| 1. 클러스터 정의 | 12개 페르소나 컨셉을 텍스트로 확정 (예: "차분한 독서가, 20대 여성, 안경, 차분한 색상") |
| 2. 마스터 시트 생성 | 클러스터별 캐릭터 시트 1장 (시드 + 스타일 프롬프트 고정). 이게 **레퍼런스 원본** |
| 3. 진화 5단계 파생 | sref(MJ) / IP-Adapter(SD) / redux(Flux)로 동일 캐릭터의 5단계 생성 |
| 4. 디자이너 보정 | 외주 1인 / 컬러·크롭·배경제거 정리 (자산 1장당 짧게) |
| 5. 액세서리 별도 생성 | 동일 스타일 톤으로 투명 PNG 생성 |
| 6. 자산 메타 커밋 | `assets/character/{cluster}/{level}.png` + 프롬프트·시드·sref ID를 `.meta.json`으로 함께 커밋 — **재현 가능성 보장** |

#### 도구 비교 (Phase 1 PoC로 결정)

| 도구 | 일관성 | 비용 | 라이선스 (상업) | 비고 |
| ---- | ------ | ---- | --------------- | ---- |
| Midjourney | sref/cref로 양호 | $30~60/월/시트 | Pro 이상 OK | 작업 속도 빠름 |
| Stable Diffusion + IP-Adapter | 가장 통제 가능 | 자체 호스팅 시 거의 무료 | 모델별 상이 | 셋업 부담, 운영 인력 필요 |
| Flux (redux/depth) | 최신, 품질 최상위 | 사용량 과금 | 모델별 확인 | 캐릭터 일관성 도구 성숙 중 |

→ **Phase 1 PoC**: 클러스터 1~2개로 5단계 시퀀스 시범 생성 후, 진화 연속성이 사람 눈으로 자연스러운지 검증 → 도구 확정.

#### 가장 큰 리스크

**진화 단계 연속성**. AI 도구의 reference 기능도 100% 동일인 보장은 못 함. 사람이 "이건 같은 캐릭터의 성장이다"로 받아들이지 못하면 본 기획의 핵심 메커니즘(매몰비용 자극)이 약해진다. PoC에서 반드시 사전 검증할 것.

## 2. 광고 수익화 전략 (1-2)

> **변경 확정 (2026-05-17)**: 채팅 인라인 네이티브 광고 제거.
> 대신 **Progressive Ad Gate** — 누적 토큰 비용 기반 응답 블라인드 + 리워드 광고 언블라인드 방식 도입.

### 2.1 광고 종류 (확정)

| 종류 | 위치 | 보상 | 목적 |
| ---- | ---- | ---- | ---- |
| **리워드 비디오** (AdMob Rewarded) | **채팅 Ad Gate** (응답 블라인드 해제), 진화 실패 후 재도전 보너스, 혜택존 코인 충전 | 30~50 코인 + 응답 언블라인드 | 핵심 수익원 |
| **인터스티셜** (AdMob Interstitial) | 진화 결과 발표 직전, 채팅 세션 종료 시 | 없음 | 전환 지점 보조 수익 |

> 네이티브 인라인 광고는 **제거**. 채팅 UX 방해 + 수익 기여 대비 이탈률이 높음.
> 채팅 내 수익화는 Ad Gate + 쿠팡 큐레이션(§3)으로 대체.

---

### 2.2 Progressive Ad Gate — 핵심 메커니즘

#### 개념
누적 토큰 사용 비용이 임계치(threshold)를 초과하면 **다음 AI 응답을 블라인드** 처리.
유저가 리워드 광고를 시청하면 블라인드가 해제되고, 광고 수익이 API 비용을 커버.

#### 사용자 플로우

```
[유저 채팅]
  ↓
[Backend] LLM 응답 생성 + 토큰 비용 누산
  session_token_cost += this_response_cost
  ↓
  ├─ session_token_cost < THRESHOLD  →  정상 응답 (SSE 전송)
  │
  └─ session_token_cost >= THRESHOLD →  ad_required: true 플래그와 함께 응답 전송
       session_token_cost 리셋 = 0
       ↓
[Frontend] Ad Gate 렌더링
  ┌─────────────────────────────────────┐
  │ AI: 좋은 질문이에요! 먼저 핵심은...  │  ← 앞 2줄 teaser (블라인드 전)
  │ ████████████████████████████████   │  ← 나머지 응답 blur 처리
  │ ████████████████████               │
  │                                     │
  │  💡 전체 답변 보기                   │
  │  [▶ 광고 시청하기 (30초)]            │
  └─────────────────────────────────────┘
       ↓ 광고 시청 완료
  AdMob SSV 콜백 → BE 코인 지급
       ↓
  blur 해제 + 코인 획득 토스트 (+30코인)
```

#### 토큰 비용 계산식 및 임계치

**전제값 (가설, 실측 후 조정)**
- 리워드 비디오 eCPM: 12,000원 / 1,000회 = **12원/시청**
- LLM 비용: mini ≈ 2원/msg, premium ≈ 30원/msg
- 안전계수: 1.5배
- **AD_GATE_THRESHOLD = 12원 × 1.5 = 18원** (누적 비용 임계치)

**Lv별 메시지당 평균 비용 및 게이트 주기**

```
E[Cost_n] = p_n × 30 + (1 - p_n) × 2
```

| Lv | premium 비율 p | E[Cost] (원/msg) | 게이트 트리거 주기 (이론) | UX 최소 보장 |
| -- | --------------- | ---------------- | ------------------------- | ------------ |
| 1  | 0%              | 2원              | 9 messages                | 9 messages   |
| 2  | 5%              | 3.4원            | 5 messages                | 5 messages   |
| 3  | 20%             | 7.6원            | 2-3 messages              | 3 messages   |
| 4  | 50%             | 16원             | 1-2 messages              | 3 messages   |
| 5  | 80%             | 24.4원           | < 1 message (매 응답)     | 3 messages   |

> **UX 최소 보장**: 연속 게이트는 최소 3메시지 간격 보장 (고레벨에서도 모든 응답 블라인드 방지).
> 백엔드에서 `last_gate_message_seq` 기록, 3메시지 미만이면 gate 스킵.

#### FE 블라인드 구현 방식

- **teaser**: 첫 1~2줄(약 80자)은 항상 노출 (FOMO 유발)
- **blur**: 나머지 텍스트에 Gaussian blur (sigma 8~12px) + 클릭 비활성
- **overlay**: 반투명 카드 (배경 dim) + 버튼 (AdMob Rewarded Ad 로드 후 활성)
- **언블라인드**: 리워드 광고 완료 콜백 수신 직후 blur 애니메이션 해제 (로컬 처리 — 이미 텍스트는 메모리에 존재)
- **SSV**: 코인 지급은 BE SSV 콜백 경로로만 (blur 해제와 분리)

#### Remote Config 운영 키

```
AD_GATE_THRESHOLD = 18        // 누적 비용 임계치 (원)
AD_GATE_MIN_MSG_GAP = 3      // 최소 메시지 간격
AD_GATE_TEASER_CHARS = 80    // teaser 노출 글자 수
AD_GATE_REWARD_COIN = 30     // 광고 시청 보상 코인
```

### 2.3 어뷰징 방지
- 누적 비용 계산 + gate 판단은 **백엔드**에서만 처리 (클라이언트 조작 불가)
- 리워드 광고 코인 지급은 **AdMob SSV 콜백**으로만 (blur 해제와 별개)
- 동일 IP/디바이스 일일 리워드 시청 캡 (예: 30회)
- blur는 UX gate이지 콘텐츠 암호화가 아님 — 탈취해도 가치 없는 구조 유지 (응답 품질은 진화 단계 기반이므로)

## 3. 쿠팡 파트너스 큐레이션 (1-3)

### 3.1 사용자 플로우

```
[유저 입력] "남자친구 30대 생일선물 골라줘"
        ↓
[Backend] LLM 호출 + 동시에 의도 분류기(intent classifier) 호출
        ↓
        ├─ 의도 = SHOPPING → 쿠팡 검색 키워드 추출 ("30대 남자 생일선물")
        │       ↓
        │   쿠팡 파트너스 API: searchProducts(keyword)
        │       ↓
        │   상위 3개 상품 메타 + 트래킹 링크 생성
        │       ↓
        └─ 의도 ≠ SHOPPING → 일반 답변만
                ↓
[Backend → Frontend] SSE 스트림 다중 페이로드
        - 텍스트 토큰 (LLM 응답)
        - 상품 카드 페이로드 (있을 경우)
        ↓
[Frontend] 텍스트 렌더링 후 상품 카드 컴포넌트 append
        ↓
        ┌─[ 상품 카드 1 ]────────┐
        │ [썸네일]                │
        │ 제목 (2줄 ellipsis)     │
        │ 가격                    │
        │ [쿠팡 최저가 확인하기]  │  ← 트래킹 링크 (Custom Tab으로 오픈)
        └────────────────────────┘
        ┌─[ 카드 2, 3 ]──────────┐
        ...
        하단 고정 문구:
        "이 포스팅은 쿠팡 파트너스 활동의 일환으로,
         이에 따른 일정액의 수수료를 제공받습니다."
```

### 3.2 의도 분류 (Intent Classifier)

LLM 응답을 매번 쿠팡 검색에 태우면 비용/노이즈가 큼. 두 가지 안:

**옵션 A: LLM 자체에 함수 호출(Function Calling)**
- 프롬프트에 `recommend_products(keyword: string)` 도구 정의
- LLM이 쇼핑 의도를 감지하면 도구 호출, 백엔드가 받아서 쿠팡 API 호출
- 장점: 정확도 높음, 키워드 추출도 동시 / 단점: premium 모델일수록 비용 ↑

**옵션 B: 경량 분류기 (가성비 mini 별도 호출)**
- mini 모델로 "이 발화가 쇼핑 의도인가? 키워드는?" 분류만 별도 호출
- 장점: 비용 통제 쉬움 / 단점: 한 메시지에 2회 호출 (latency ↑)

→ **Phase 1: 옵션 A 권장** (이미 stream 중이므로 자연스러움)

### 3.3 노출 조건 (필수)

| 조건 | 처리 |
| ---- | ---- |
| 쇼핑 의도 미감지 | 카드 미노출 |
| 쿠팡 검색 결과 < 3개 | 결과 수만큼만 노출 |
| 검색 키워드가 부적합(성인/의약품 등) | 차단 리스트로 필터 |
| 필수 고지 문구 | **항상 카드 하단에 노출** (회피 시 파트너스 정책 위반) |

### 3.4 데이터 모델 (개요)

```
ChatMessage
  ├─ id, role, content, ...
  └─ attachments: List<MessageAttachment>
       └─ CoupangProductCard
            ├─ productId, title, imageUrl
            ├─ priceWon
            ├─ trackingUrl  (서버에서 partner_id 포함하여 생성)
            └─ disclosureText (고정 문구)
```

### 3.5 정산/트래킹
- 트래킹 링크 클릭 이벤트는 **앱 → 백엔드 로깅**도 수행 (쿠팡 측 정산과 대조용)
- 광고 차단 등 환경에서 카드 비노출은 OK이나, 고지 문구는 LLM 답변 본문 마지막에 fallback 삽입

## 4. 단계별 모델 라우팅 — 백엔드 책임

> CC-283 기준 최신 손익 방어 정책은 [06-ai-chat-profit-guard.md](./06-ai-chat-profit-guard.md)를 따른다.
> 아래 내용은 초기 컨셉이며, 실제 구현에서는 `displayLevel`, `effectiveLevel`, 포만도, 퀄리티 버젯, Ad Gate 상태를 함께 고려한다.

```
ChatService.generate(userId, message):
  user = userRepo.find(userId)
  premium_ratio = ratioByLevel[user.evolution_level]   // 캐싱
  use_premium = secureRandom() < premium_ratio          // 서버 난수
  provider = use_premium ? premiumProvider : miniProvider
  return provider.stream(message)
```

- **클라이언트는 어떤 모델이 호출되는지 알지 못함** (응답 품질만 체감)
- A/B 시 `premium_ratio` 테이블을 Remote Config로 운영자가 조정 가능

## 5. 미결정 / 향후 결정 필요

- **AI 이미지 도구 확정**: Midjourney / SD+IP-Adapter / Flux 중 PoC 후 결정 (§1.4 참조)
- **페르소나 클러스터 정의**: 8개? 12개? 컨셉 텍스트 확정 필요
- **클러스터 변경 정책**: 1회 할당 후 불변 vs Phase 2에 유료 리롤 아이템 도입
- **EXP 산식**: 메시지당 +1? 발화 길이 비례? 일일 캡?
- **진화석 가격**: 코인 200? 광고 시청 1회 = 진화석 1개?
- **광고 수치 검증**: 위 eCPM/비용은 모두 가설값. 실측 후 룰 재설계 필요
- **쿠팡 카드 노출 빈도 캡**: 한 세션에 너무 자주 뜨면 거슬림 — 캡 정책 필요
