## 2. 사용자 Story

> 슈퍼 관리자는 업무 범위에 맞는 접근 통제를 위해 관리자 역할과 세부 권한을 관리할 수 있다.

- 사용자: 슈퍼 관리자
- 목적: 업무 범위에 맞는 접근 통제
- 행동: 역할과 세부 권한(조회·변경·다운로드) 구성
- 기대 결과: 구성된 권한이 다음 API 요청부터 적용되고, 무권한 호출은 403으로 거부되며 메뉴가 제한된다
- 우선순위: P0
- 원문 근거: INTAKE-001 §7.1 US-ADM-AUTH-003

---

## 3. 기능 범위

### 포함

- 역할 생성·수정과 조회·변경·다운로드 권한 부여
- 다음 API 요청부터 즉시 적용
- 서버 측 권한 검증(403 Forbidden)
- 로그인 시 허용 메뉴·동작만 노출

### 제외

- 계정에 역할을 배정하는 흐름 → REQ-002(계정 생성 시 역할 입력)
- 서비스 회원 권한(해당 없음)

## 6. 사용자·시스템 흐름

### 정상 흐름

1. 슈퍼 관리자가 역할·권한 화면에서 권한을 구성한다.
2. 시스템이 실행자 권한과 입력을 검증한다.
3. 권한 구성을 저장하고 다음 요청부터 적용한다.
4. 변경 결과를 표시한다.
5. 변경 내용을 감사 기록으로 저장한다.

### 예외 흐름

| 흐름 ID | 발생 조건 | 사용자 표출 | 시스템 처리 | 복구 방법 |
|---|---|---|---|---|
| FLOW-E01 | 권한 없는 관리자가 API 직접 호출 | 403 | 거부·기록 | 권한 부여 후 재시도 |
| FLOW-E02 | 존재하지 않는 역할 대상 | 대상 없음 안내 | 거부 | 역할 생성 후 재시도 |
