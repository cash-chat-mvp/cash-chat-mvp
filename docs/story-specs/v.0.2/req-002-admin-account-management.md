## 2. 사용자 Story

> 슈퍼 관리자는 운영 인력의 접근 통제를 위해 관리자 계정을 생성하고 비활성화할 수 있다.

- 사용자: 슈퍼 관리자
- 목적: 운영 인력의 접근 통제
- 행동: 관리자 계정 생성·비활성화
- 기대 결과: 중복 없는 계정이 생성되고, 비활성화 시 모든 세션이 만료되며 새 로그인이 차단된다
- 우선순위: P0
- 원문 근거: INTAKE-001 §7.1 US-ADM-AUTH-002

---

## 3. 기능 범위

### 포함

- 관리자 계정 생성(이름·로그인 ID·역할 입력, 중복 검증)
- 계정 비활성화(사유 입력, 전체 세션 만료, 신규 로그인 차단)
- 자기 계정 비활성화 거부

### 제외

- 역할·세부 권한 정의 → REQ-003
- 로그인·잠금 → REQ-001
- 계정 삭제(이번 버전 범위 아님, 비활성화로 갈음)

## 4. 실행 조건

- 실행 주체: 슈퍼 관리자(관리자 계정 관리 권한 보유)
- 선행 조건: 로그인 상태(REQ-001), 역할 정의 존재(REQ-003)
- 필요한 권한: 관리자 계정 관리 권한
- 추가 인증 여부: 위험 작업 추가 확인 여부는 감사·보안 정책과 정합 필요
- 대상의 허용 상태: 생성은 미존재 ID, 비활성화는 활성 계정

## 6. 사용자·시스템 흐름

### 정상 흐름

1. 슈퍼 관리자가 계정 관리 화면에서 생성 또는 비활성화를 시작한다.
2. 시스템이 실행자 권한과 입력(ID 중복·사유·자기 계정 여부)을 검증한다.
3. 계정을 생성하거나 비활성화(세션 전체 만료)를 수행한다.
4. 결과를 목록에 반영해 표시한다.
5. 변경 내용을 감사 기록으로 저장한다.

### 예외 흐름

| 흐름 ID | 발생 조건 | 사용자 표출 | 시스템 처리 | 복구 방법 |
|---|---|---|---|---|
| FLOW-E01 | 로그인 ID 중복 | 중복 안내 | 생성 거부 | 다른 ID로 재시도 |
| FLOW-E02 | 자기 계정 비활성화 시도 | 거부 안내 | 거부, 기록 | 다른 슈퍼 관리자가 수행 |
| FLOW-E03 | 권한 없음 | 403 안내 | 거부, 기록 | 권한 부여 후 재시도 |
