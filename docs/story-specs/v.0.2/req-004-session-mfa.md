## 2. 사용자 Story

> 관리자는 계정 탈취와 방치된 로그인 정보의 악용 방지를 위해 세션과 추가 인증을 안전하게 관리할 수 있다.

- 사용자: 관리자
- 목적: 계정 탈취·방치된 로그인 정보의 악용 방지
- 행동: 세션 유휴 만료·추가 인증·로그아웃 관리
- 기대 결과: 유휴 세션이 만료되고, 추가 인증 통과 후에만 세션이 발급되며, 로그아웃 시 세션이 무효화된다
- 우선순위: P1
- 원문 근거: INTAKE-001 §7.1 US-ADM-AUTH-004

## 3. 기능 범위

### 포함

- 유휴 시간 초과 세션 만료(다음 API 호출 시 재로그인 요구)
- 비밀번호 인증 후 추가 인증 수단 검증 → 세션 발급
- 로그아웃 시 서버 세션 무효화·재사용 차단

### 제외

- 추가 인증 수단 자체의 선택·등록 UX 상세(UNR-009 결정 후 구체화)
- 로그인 기본 흐름 → REQ-001

## 6. 사용자·시스템 흐름

### 정상 흐름

1. 관리자가 비밀번호 인증을 통과한다.
2. 시스템이 등록된 추가 인증 수단을 검증한다.
3. 세션을 발급한다.
4. 유휴 시간 초과 후 첫 API 호출 시 세션을 만료시키고 재로그인을 요구한다.
5. 로그아웃 시 서버 세션을 무효화하고 이벤트를 감사 기록으로 저장한다.

### 예외 흐름

| 흐름 ID | 발생 조건 | 사용자 표출 | 시스템 처리 | 복구 방법 |
|---|---|---|---|---|
| FLOW-E01 | 추가 인증 실패 | 실패 안내 | 세션 미발급, 기록 | 재시도(횟수 정책 DEC-003) |
| FLOW-E02 | 만료 세션으로 API 호출 | 재로그인 요구 | 401 처리 | 재로그인 |
| FLOW-E03 | 무효화된 토큰 재사용 | 재로그인 요구 | 거부·기록 | 재로그인 |
