## 2. 사용자 Story

> 관리자는 인가된 운영 시스템 접근을 위해 관리자 계정으로 로그인할 수 있다.

- 사용자: 관리자
- 목적: 인가된 운영 시스템 접근
- 행동: 관리자 계정(아이디·비밀번호)으로 로그인
- 기대 결과: 인증 세션이 발급되고 허용된 초기 화면 정보가 반환된다
- 우선순위: P0
- 원문 근거: INTAKE-001 §7.1 US-ADM-AUTH-001

---

## 3. 기능 범위

### 포함

- 아이디·비밀번호 로그인과 인증 세션 발급
- 로그인 성공 시 허용된 초기 화면 정보 반환
- 인증 실패 응답 동일화(원인 미노출)
- 반복 실패 시 계정 잠금과 시도 내역 기록

### 제외

- 추가 인증(MFA)·세션 정책 관리 → REQ-004
- 관리자 계정 생성·비활성화 → REQ-002
- 서비스 회원 로그인(회원·제재 도메인)

---

## 4. 실행 조건

- 실행 주체: 관리자(인증 전 사용자)
- 선행 조건: 활성 상태의 관리자 계정 존재
- 필요한 권한: 없음(인증 진입점)
- 추가 인증 여부: REQ-004에서 정의
- 대상의 허용 상태: 계정 상태 `활성`(잠금·비활성 계정은 거부)

## 6. 사용자·시스템 흐름

### 정상 흐름

1. 관리자가 로그인 화면에서 아이디·비밀번호를 입력한다.
2. 시스템이 계정 존재·상태(활성/잠금/비활성)·비밀번호를 검증한다.
3. 인증 세션을 발급한다.
4. 허용된 초기 화면 정보를 반환한다.
5. 로그인 성공·실패 이벤트를 감사 기록으로 저장한다.

### 예외 흐름

| 흐름 ID | 발생 조건 | 사용자 표출 | 시스템 처리 | 복구 방법 |
|---|---|---|---|---|
| FLOW-E01 | 아이디 미존재·비밀번호 불일치 | 동일한 일반 실패 문구 | 실패 카운트 증가, 시도 기록 | 올바른 자격증명 재시도 |
| FLOW-E02 | 실패 누적 잠금 도달 | 잠금 안내(표시 범위는 DEC-002) | 계정 잠금, 기록 | 정책 시간 경과 후 재시도 |
| FLOW-E03 | 비활성 계정 | 일반 실패 문구 | 거부, 기록 | 슈퍼 관리자에게 활성화 요청 |

Scenario: 정상 로그인 (AC-01)

Scenario: 인증 실패 응답 동일화 (AC-02)
  Given 존재하지 않는 아이디 또는 불일치 비밀번호가 주어진다

  Given 동일 계정의 인증 실패가 정책 횟수에 도달했다
  When 로그인을 다시 시도한다
