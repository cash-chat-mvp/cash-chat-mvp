# 채팅 완료 보상 피드백 UI/UX 개편 설계

> 작성일 2026-06-26 · 대상 Android/iOS · 관련 작업 CC-352

## 1. 목표

현재 채팅 완료 보상 연출은 작은 원형 입자 8개가 0.9초 동안 고정 위치에서 사라지는 방식이라 사용자가 무엇을 획득했는지 인식하기 어렵다.

정상적인 AI 응답 완료 시 다음 내용을 명확하게 전달한다.

- 포인트 `🪙 +1`
- 진화 경험치 `⭐ +1`
- 보상이 마지막 AI 답변에서 발생했다는 인과관계
- 보상이 상단 HUD 잔액에 반영됐다는 결과

에너지는 채팅 완료 보상이 아니라 채팅 사용 시 소비되는 자원이므로 획득 연출에 포함하지 않는다.

## 2. 핵심 연출

### 2.1 버블 보상 배지

마지막 AI 답변 버블의 오른쪽 위에서 두 개의 보상 배지가 순차적으로 나타난다.

- `🪙 +1`: 지름/높이 기준 44dp 이상
- `⭐ +1`: 지름/높이 기준 44dp 이상
- 아이콘은 24~28dp, 숫자는 16sp 이상의 굵은 글꼴
- 배지는 반투명한 어두운 배경, 밝은 외곽선과 글로우를 사용한다.
- Android와 iOS 모두 최소 터치 영역과는 별개로 시각 크기를 동일하게 유지한다.

기존 8~16px 수준의 작은 원은 핵심 정보로 사용하지 않고 보상 배지 주변의 보조 파티클로만 사용한다.

### 2.2 이동

- 첫 0.25초: 버블 위에서 110% 크기로 팝업
- 다음 0.9초: 곡선 경로로 상단 HUD 방향 이동
- 마지막 0.25초: HUD 칩에 흡수되며 페이드
- 전체 연출 시간: 약 1.4초
- 코인과 별은 0.12초 간격으로 출발해 서로 겹치지 않게 한다.

정확한 HUD 좌표를 레이아웃에서 측정해 이동 경로의 도착점으로 사용한다. 좌표 측정이 불가능한 상태에서는 화면 상단의 각 자원 칩 방향으로 이동한다.

### 2.3 HUD 반응

보상 배지가 도착할 때 해당 HUD 칩을 별도로 반응시킨다.

- 칩 크기 1.0 → 1.15 → 1.0
- 배경 글로우 1회
- 이전 값에서 새 값으로 숫자 카운트업
- 포인트와 경험치의 반응 시점을 각 배지 도착 시점과 맞춘다.

## 3. 트리거와 데이터

연출 트리거는 기존 `ChatStore.streamCompletedCount`를 유지한다. 정상 `Done` 이벤트에서만 실행하고 스트림 오류·취소에서는 실행하지 않는다.

현재 정책이 포인트 +1, 경험치 +1로 고정돼 있으므로 서버의 실제 HUD 상태를 재조회하면서 기본 표시값을 사용한다. 향후 `done` 이벤트에 `pointDelta`, `expDelta`가 포함되면 실제 값을 우선한다.

연출 시작을 HUD 재조회 완료 뒤까지 지연하지 않는다.

1. `Done` 수신 즉시 버블 보상 배지 연출 시작
2. 동시에 HUD 재조회
3. 새 잔액 도착 시 HUD 카운트업
4. 조회 실패 시 배지 연출은 완료하되 HUD 숫자는 기존 값을 유지하고 다음 정상 갱신에서 복구

## 4. 화면 위치

- 보상 원점은 마지막으로 완료된 AI 답변 버블이다.
- 사용자가 과거 메시지를 보고 있어 해당 버블이 화면 밖이면 강제 스크롤하지 않는다.
- 화면 밖인 경우 하단 중앙에서 보상 토스트를 표시하고 HUD로 이동시킨다.
- 네이티브 광고가 응답 뒤에 삽입돼도 보상 원점은 광고가 아니라 완료된 AI 답변이다.
- 키보드와 입력창 위에서도 배지가 잘리지 않도록 채팅 화면 최상위 오버레이에 그린다.

## 5. 시각·촉각 피드백

- 포인트: 금색 계열
- 진화 경험치: 보라색·청록색 계열
- 배지 등장 시 약한 햅틱
- HUD 흡수 시 자원별 짧은 단발 햅틱
- 시스템 Reduce Motion 활성 시 곡선 이동 대신 버블 배지 표시와 HUD 크로스페이드로 대체
- 색상 외에도 아이콘과 `+N` 텍스트를 항상 표시한다.

## 6. 컴포넌트 구조

- `ChatRewardEvent`: 완료된 메시지 ID, 포인트/경험치 변화량
- `RewardOriginTracker`: 마지막 AI 답변과 화면 좌표
- `RewardTokenOverlay`: 큰 보상 배지와 이동 애니메이션
- `RewardParticleLayer`: 작은 보조 파티클
- `RewardHudChip`: 카운트업, 펄스와 도착 피드백

Android Compose와 SwiftUI에서 같은 데이터 흐름과 타이밍을 사용하되 각 플랫폼 애니메이션·햅틱 API로 구현한다.

## 7. 검증

- 정상 완료에서 한 번만 실행
- 오류·취소·재시도 중복 완료에서 중복 보상 표시 방지
- 코인과 경험치 배지가 최소 44dp로 렌더링되는지 확인
- 밝은/어두운 배경에서 아이콘과 `+1` 대비 확인
- 버블이 화면 안/밖인 경우의 원점 처리
- 네이티브 광고 삽입 시 원점 유지
- HUD 조회 성공/실패 시 동작
- 작은 화면, 큰 글꼴, 키보드 표시, Reduce Motion 검증
