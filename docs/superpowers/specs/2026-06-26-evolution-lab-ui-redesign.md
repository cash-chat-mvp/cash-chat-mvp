# 캐릭터 진화 화면 UI/UX 개편 설계

> 작성일 2026-06-26 · 대상 Android/iOS · 관련 작업 CC-352

## 1. 목표

현재 진화 화면은 데이터 로드 전후 상태와 버튼 활성 여부가 불명확하고, iOS는 진화 과정과 결과 피드백이 거의 없다. 양 플랫폼을 동일한 미래형 분석 장치 콘셉트로 개편한다. 내부 디자인 방향은 Evolution Lab으로 관리하되 사용자에게 노출되는 화면명은 **캐릭터 진화**로 통일한다.

사용자는 화면을 보는 즉시 다음을 이해할 수 있어야 한다.

1. 현재 캐릭터와 레벨
2. 다음 진화 형태
3. 보유 경험치와 시도 비용
4. 기본 성공 확률과 획득 가능한 타이밍 보너스
5. 지금 시도할 수 없는 이유
6. 조작 결과와 최종 진화 판정

## 2. 디자인 방향

어두운 남색 배경 위에 보라색·청록색 글로우를 사용한다. 캐릭터는 화면 중앙의 원형 분석 장치 안에 배치하고, 원형 링·스캔 라인·입자 효과로 미래적인 실험실 인상을 만든다.

정보는 장식보다 우선한다.

- 상단: 닫기, `캐릭터 진화`, 보조 메뉴
- 중앙: 현재 캐릭터, 레벨, 성장 단계, 다음 형태 미리보기
- 하단 정보 영역: 경험치 진행도, 기본 성공 확률, 시도 비용, 성공 보상
- 하단 고정 CTA: 길게 눌러 진화

Android와 iOS는 플랫폼 컴포넌트와 햅틱 API는 각각 사용하되 정보 구조, 상태 문구, 색상 의미와 연출 타임라인을 일치시킨다.

## 3. 화면 상태

### 3.1 Loading

- 캐릭터 실루엣과 정보 카드 스켈레톤을 표시한다.
- CTA는 숨기거나 `진화 정보를 분석하고 있어요` 상태로 표시한다.
- 기본값 `Lv.1`이나 활성처럼 보이는 파란 버튼을 노출하지 않는다.

### 3.2 Load error

- `진화 정보를 불러오지 못했어요`와 재시도 버튼을 표시한다.
- 화면 전체를 닫지 않고 같은 위치에서 재조회할 수 있어야 한다.

### 3.3 Insufficient EXP

- 진행바에 `현재 / 필요` 값을 표시한다.
- CTA는 비활성 스타일과 함께 `경험치 N이 더 필요해요`로 표시한다.
- 보조 행동으로 `채팅으로 경험치 모으기`를 제공하고 화면을 닫아 채팅으로 돌아간다.

### 3.4 Ready

- CTA 문구는 `길게 눌러 진화`이다.
- 기본 확률과 `타이밍 보너스 최대 +10%`를 함께 표시한다.
- CTA 아래에 실제 소모 경험치를 명시한다.

### 3.5 Max level

- 캐릭터 주변 글로우와 완료 배지를 유지한다.
- CTA 대신 `최고 진화 단계 달성`을 표시한다.
- 비용, 확률, 타이밍 게이지는 숨긴다.

## 4. 길게 누르기와 타이밍 판정

### 4.1 입력 규칙

- 사용자가 CTA를 누르면 에너지 주입이 시작된다.
- 누른 뒤 0.6초가 되기 전에 손을 떼면 취소하며 경험치를 소모하지 않는다.
- 0.6초 이후 손을 떼면 Normal, Great, Perfect 중 하나로 판정하고 진화를 요청한다.
- 타이밍을 놓쳐도 진화는 취소되지 않으며 기본 성공 확률로 시도한다.
- 요청이 전송된 뒤에는 중복 입력을 막는다.

### 4.2 보너스

| 등급 | 게이지 영역 | 성공 확률 보너스 |
|---|---:|---:|
| Perfect | 중앙 10% | +10%p |
| Great | Perfect 주변을 포함한 중앙 24%에서 Perfect 제외 | +5%p |
| Normal | 나머지 활성 영역 | +0%p |
| Cancel | 0.6초 이전 해제 | 요청 없음 |

최종 성공 확률은 100%를 넘지 않는다. UI는 입력이 끝난 즉시 등급과 예상 최종 확률을 표시하되, 서버 응답을 최종 판정으로 사용한다.

## 5. 연출 타임라인

### 5.1 누르는 동안

- 원형 링이 회전하며 중심으로 수축한다.
- 캐릭터 글로우와 입자 밀도가 단계적으로 증가한다.
- 타이밍 마커가 게이지 위를 왕복한다.
- 햅틱은 약한 펄스에서 시작해 Perfect 구간 근처에서 강해진다.
- `에너지 주입 중`과 `빛나는 구간에서 손을 떼세요`를 표시한다.

### 5.2 손을 뗀 직후

- Normal: 중립색 펄스와 `기본 동기화`
- Great: 보라색 펄스와 `정밀 동기화 +5%`
- Perfect: 금색 플래시와 `완벽한 동기화 +10%`

등급 피드백 뒤 서버 결과를 기다리는 동안 캐릭터 스캔과 링 회전을 지속한다.

### 5.3 성공

- 짧은 화이트 플래시 후 새 캐릭터 형태로 전환한다.
- 강한 단발 햅틱과 위로 퍼지는 파티클을 사용한다.
- 결과 패널에서 새 레벨, 사용 경험치, 에너지 보너스를 각각 표시한다.
- 확인 후 캐릭터 진화 화면의 갱신된 상태로 복귀한다.

### 5.4 실패

- 채도를 잠시 낮추고 캐릭터를 짧게 두 번 흔든다.
- 성공보다 짧고 약한 이중 햅틱을 사용한다.
- `이번 동기화는 실패했어요`와 사용 경험치를 표시한다.
- `다시 시도`와 `채팅으로 경험치 모으기`를 제공한다.
- 실패를 사용자의 타이밍 실수로 단정하지 않는다. Perfect 등급이어도 확률 판정상 실패할 수 있음을 결과 패널에서 명확히 보여준다.

## 6. 상태 및 컴포넌트 구조

플랫폼별 화면 상태는 같은 의미를 갖는다.

- `Loading`
- `LoadError`
- `InsufficientExp`
- `Ready`
- `Charging(progress, markerPosition)`
- `Resolving(timingGrade, finalRate)`
- `Success(result)`
- `Failure(result)`
- `MaxLevel`

UI는 다음 단위로 분리한다.

- `EvolutionHero`: 캐릭터, 단계, 다음 형태
- `EvolutionProgress`: 경험치 진행도와 부족량
- `EvolutionStats`: 기본 확률, 보너스, 비용
- `TimingGauge`: 마커 이동과 등급 영역
- `HoldToEvolveButton`: press/drag/release 입력
- `EvolutionResultPanel`: 성공·실패 결과
- `EvolutionEffects`: 링, 스캔, 파티클, 플래시

타이밍 측정과 UI 애니메이션은 플랫폼에서 수행하지만, 서버 응답의 등급·보너스·최종 확률이 클라이언트 계산보다 우선한다.

## 7. 접근성과 안전장치

- 색상만으로 등급과 결과를 구분하지 않고 텍스트와 햅틱을 함께 사용한다.
- Reduce Motion 활성 시 파티클·플래시·회전을 축소하고 크로스페이드로 대체한다.
- 시스템 무음 상태에서도 시각과 햅틱만으로 의미가 전달돼야 한다.
- 큰 글꼴과 작은 화면에서는 본문이 스크롤되고 CTA는 안전 영역 위에 고정된다.
- 길게 누르는 동안 화면 밖으로 드래그하면 시간 경과(0.6초 이상)와 관계없이 항상 취소(Cancel)로 판정하여 요청을 전송하지 않는다.
- 네트워크 오류 시 같은 idempotency key로 안전하게 재시도할 수 있어야 한다.

## 8. 백엔드 의존성

백엔드는 이 작업에서 직접 수정하지 않는다. 타이밍 보너스를 실제 성공 확률에 반영하려면 서버 검증이 필요하므로 별도 요청 문서에 계약을 추가한다.

프론트가 먼저 배포되므로 화면 진입 시 `POST /api/evolution/timing-sessions`의 지원 여부를 확인한다.

- API 성공: 길게 누르기, 타이밍 게이지와 보너스 안내를 활성화한다.
- API 미지원(404/405 등): 기존 진화 API를 사용한 기본 확률 시도로 자동 전환한다.
- 일시적 네트워크 오류/5xx: 타이밍 보너스를 적용하지 않고 기본 확률 시도를 제공하되, 보너스가 적용되는 것처럼 오해할 연출이나 문구를 노출하지 않는다.

별도 기능 플래그나 앱 재배포 없이 백엔드 API가 배포되면 다음 화면 진입부터 타이밍 기능이 자동 활성화된다. 세션 API가 성공했더라도 타이밍 진화 요청이 서버에서 미지원 오류를 반환하면 비용 차감 여부를 확인할 수 없으므로 자동 재시도하지 않고 명확한 오류를 표시한다.

## 9. 검증

- Android Compose UI 테스트: Loading, 오류, 부족, Ready, Max level
- iOS View/ViewModel 테스트: 동일 상태와 버튼 의미
- press duration 및 Normal/Great/Perfect 경계 단위 테스트
- 0.6초 이전 취소와 중복 요청 방지 테스트
- 서버 응답 등급이 로컬 예상 등급과 다를 때 서버 값을 표시하는 테스트
- 작은 화면, 큰 글꼴, Reduce Motion 스모크 테스트
- 실제 기기에서 햅틱 강도와 2초 내외의 전체 연출 체감 확인
