- 대상 엔드포인트: `POST /api/v1/chat/stream` (SSE)

## 1. 배경 / 무엇을 하려는가

채팅 응답 중 일부에 대해, **응답을 보여주기 전에 네이티브 광고를 먼저 노출**하고
**최소 X초 뒤에 응답을 시작**하는 "프리롤 광고" 동선을 도입하려 한다.

- **어떤 응답에 프리롤을 적용할지는 서버가 결정**한다(클라 정책 아님).
  → 운영/실험으로 노출 대상·비율을 제어하기 위함.
- FE는 광고를 띄우는 동안 응답 토큰을 **백그라운드로 미리 받아 버퍼링**하다가,
  X초 경과 후 화면에 푼다. 따라서 **서버는 토큰을 평소대로 즉시 보내도 된다**(지연 불필요).

## 2. 백엔드에 필요한 대응

### 2.1 신규 SSE 이벤트: `event: preroll`

스트림 시작 직후(첫 `token` 이전)에, 프리롤 대상 응답이면 아래 이벤트를 **1회** 보낸다.

```
event: preroll
data: {"adType":"native"}
```

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `adType` | string | Y | 현재는 `"native"` 고정. 향후 확장 대비 |

- **이벤트는 "이 응답에 프리롤을 적용하라"는 트리거만 담당**한다.
- **광고 노출 시간(초)은 이벤트에 싣지 않는다.** FE는 노출 시간을 **Firebase Remote Config
  (`preroll_ad_delay_sec`)** 에서 읽는다 → 서버/운영이 코드·배포 없이 RC로 조정.
- **위치**: 반드시 첫 `token` 이벤트보다 **먼저** 전송. 이후 토큰은 평소대로 스트리밍.
- **미대상 응답**: `preroll` 이벤트를 보내지 않으면 됨(기존 동작과 100% 동일).
- **호환성**: 기존 클라(미지원 버전)는 알 수 없는 `event:`를 토큰으로 처리할 위험이 있으므로,
  **FE 지원 버전 배포 이후에만** 서버에서 `preroll` 발행을 켜야 한다(아래 4. 롤아웃).

### 2.2 기존 `gate` 이벤트와 상호배타

한 응답에 `preroll`과 `gate`(리워드 광고 잠금)를 **동시에 보내지 않는다**.
서버에서 둘 중 하나만 발행하도록 보장. (동시 수신 시 FE 우선순위 미정 → 회피 목적)

### 2.3 (선택) 노출 대상 결정 로직

- 어떤 기준으로 프리롤을 붙일지(예: 세션 첫 응답, N번째, 특정 세그먼트)는 서버/운영 정책.
- 가능하면 Remote Config 또는 서버 설정으로 **코드 배포 없이 비율 조정** 가능하도록 한다.

## 3. FE 측 처리 요약(참고)

- `ChatStreamEvent`에 `PreRollAd(adType)` 추가, `event:"preroll"` 파싱. (노출 시간은 미포함)
- 광고 버블 삽입 + X초 타이머(X=RC `preroll_ad_delay_sec`), 그 사이 토큰 버퍼링 → 만료 후 flush.
- **광고 로드 실패/no-fill → 즉시 응답 노출**(대기 없음).
- RC 키 2종: `preroll_ad_enabled`(킬스위치, 기본 false), `preroll_ad_delay_sec`(노출 시간, 기본 3).

## 4. 롤아웃 순서 (중요)

1. **FE**: `preroll` 이벤트 파싱·동작 구현 후 배포. (`preroll_ad_enabled=false`로 동작 비활성 상태 유지)
2. FE 지원 버전 보급률 충분히 확보.
3. **BE**: 프리롤 대상 응답에 `event: preroll` 발행 시작.
4. **RC**: `preroll_ad_enabled=true`로 점진 활성(실험/단계적 ramp).

> 순서를 지키지 않으면 구버전 클라가 `preroll` 데이터를 응답 본문 텍스트로 출력할 수 있음.
